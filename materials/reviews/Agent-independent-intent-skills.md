# 跨 Agent、以工程意图为中心的现成 Skills 选型

核对日期：2026-10-09。用户明确要求：不绑定 Codex、Claude、OpenCode、Zed、Qoder 等任何一种执行工具；能从代码轻易查到的信息不必形成 Wiki，长期文档记录架构设计、约束和决策原因。继续研究与选型，未安装或执行外部 Skills。

## 原文支持与建议

| 上游能力 | 原文支持 | 对当前需求的判断 |
|---|---|---|
| Matt `domain-modeling` / `grill-with-docs` | 设计过程中澄清术语，核对代码与人的陈述，及时记录决策。Glossary 不含实现细节 | 主选。用于发现隐性知识；代码能验证的是现状，人的原因仍需询问 |
| Matt ADR-FORMAT | 默认标题加 1—3 句背景、决定和原因；可选状态、备选方案、后果。明确涵盖代码不可见的约束、边界与非直觉取舍 | 直接使用精简格式，不必再创建长篇 ADR 模板 |
| Matt `writing-for-agents` | 单一事实来源；文档只缓存难查的信息，如未写明约定、选择原因、配置未表达的隐患；简单命令/文件查询留在环境中 | 与用户要求高度一致，用于治理冗长重复的上下文文件 |
| Matt `to-spec` | 阅读相关 ADR，保存实现与测试决策，避免容易过时的文件路径与代码片段 | 用于本次变更契约，不应把所有短期规格变成长期架构文档。原模板要求极长 User Stories，可能仍需本地精简约定 |
| Matt `code-review` | 比较规格和工程标准，引用依据；跳过工具已强制执行的检查 | 可保留。原文没有强制检索全部相关 ADR/设计约束，因此需要补充检索与评审入口 |
| Matt `retro` | 自动化机械约束；AGENTS.md 少用、主要放导航；提炼真实的判断规则 | 用于持续改善规则，减少累积无效 Markdown |
| Matt `handoff` | 不复制已有规格、ADR、提交、diff，改用链接；交接摘要写临时目录 | 适合短期会话接续，不是默认持久化、跨机器共享方案 |
| Humanlayer `show-me` | 按问题选择图、调用树、伪代码或 HTML 等表达 | 作为按需解释视图，不作为持久的代码结构真相副本 |
| TeamAI | 多代理分发规则、文档和 Skills；团队资产同步 | 有团队共享需求时加入；代码图谱/Wiki 不作为本方案前提 |

Matt 不是一个“自动补齐所有隐性知识”的系统。ADR 创建条件偏向难逆转、令人意外且有真实取舍；重要但容易改变的约束仍可能需要另外记录。架构原因不能从代码中推断后直接作为确定事实保存，应区分人的确认、已有证据与代理假设。

## Agent 无关的边界

内容层：仓库中的工程意图、约束、ADR、术语及其索引。它们是团队资产，与客户端无关。

方法层：尽量原样使用 Matt 与 Show Me 等上游 Skills，继续获得其更新。

接入层：每个客户端的小型导航/工具适配。Skill 工具调用、子代理、插件机制、安装目录和更新能力不同；共享 Markdown 不代表流程自动兼容。Zed 是编辑器，实际执行能力还取决于其使用的后端代理。此次 Zed/OpenCode 在线文档请求返回 403，未确认逐客户端完整能力。

当前不写多套互相复制的规则，也不承诺“一个安装命令适配所有客户端”。本地新增内容应独立于上游目录，保持来源可辨识，避免更新覆盖修改。TeamAI 是否适合全部客户端、是否需要仅用于其中一部分仍需核对。

## 最小补充候选

先以项目规则明确：中文简短输出；代码易查信息按需查；人的设计理由不得被代码推测替代；长期决策只有一个来源；相关变更必须查阅其约束与 ADR。

如果规则不足，再增加一个独立的“工程意图评审” Skill，承担：

1. 按变更定位相关边界、约束与 ADR。
2. 说明哪些不变量、前提和已接受取舍受到影响。
3. 要求论据或验证证据，指出未知项；需要改变决策时提出待确认更新，不悄悄改写原决策。
4. 将结果转为现有评审系统的说明；Gerrit API 接入独立按需处理。

这不是重新实现 Matt 的 Code Review，而是补充“代码正确但违反原始设计意图”的检查。先验证能否通过 CODING_STANDARDS.md 的引用与约定让现成评审完成，不急于写新 Skill。

## 持久知识与按需视图

长期保存：人确认的设计边界、约束与理由、备选路线、适用条件和重审触发点；有意义的验证依据。

按需生成：函数和目录说明、调用关系、代码结构图、变更解释。图只在承载无法从代码恢复的设计意图时作为正式设计记录保存。

AGENTS.md 或客户端接入文件仅放简短指针。必要时用一个轻量索引列出决策/约束主题、范围和记录位置；该索引不重述源文档，也不镜像代码结构。

## 国内组件优先级修正

Qoder/华为码道的 Wiki 是可选探索工具，不是核心知识底座；支持 Skills 的产品只按运行和接入需求选择。腾讯 TeamAI 对团队分发仍有价值，但不默认开启 Wiki/图谱。阿里、美团、华为等实践的规格、测试和评测方法可以借鉴，尚未找到符合这两条约束且完整公开的可直接安装体系。
