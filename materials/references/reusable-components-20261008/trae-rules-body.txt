You can establish rules to regulate AI's behavior within TraeCode, including code style, language and framework, interaction methods, and more, making the AI's output better aligned with your personal preferences and project requirements.
*About rules
Use cases
The main use cases for rules are as follows:
Efficiency improvement
Transform personal experience and project requirements into reusable rules, allowing a single configuration to remain effective over time, reducing communication costs with AI and manual review time.
StandardizationStructure team guidelines and project standards into rules so that the content managed by all members remains consistent in style, structure, and quality, avoiding deviations.
Quality assuranceEnsure that AI understands the project's core constraints (such as architecture design, naming conventions, code style, and more), preventing common errors.
Rule types
You can configure two types of rules: user rules and project rules.
Global rules: Global rules are rules customized for the AI based on personal usage habits and needs, aiming to make the AI's output better meet the user's personalized requirements. Global rules take effect in all projects.
Project rules: Project rules are the rules that the AI must follow for the current project, and they are only effective within the current project.

About creating rules for subdirectories
In a large project, there are usually multiple folders, each representing a different module or technology stack. If all rules (including AGENTS.md) are configured in the project root directory, it is not only difficult to maintain but may also cause exclusive rules for one module to interfere with other modules.
TraeCode supports reading the  folder in any subdirectory of the project. To configure rules for a specific module, you can directly place the rule files in that module's folder. When you mention files in that directory in a chat, or when the AI reads files in that directory while dealing with tasks, the system will automatically apply the exclusive rules in that directory.

Control the granularity of each rule's content to avoid including too much information in a single rule, keeping it clear, focused, and easy to understand.
Rules must not conflict with or override each other.
When specifying file paths, use relative paths based on the project root directory to ensure that the AI can accurately locate the file.
When referencing rules, prioritize those that are strongly related to the current chat or task.
After creating or modifying a rule, it is recommended to start a brand new chat before using it to avoid conflicts between historical context and the new rule.
If there is already a large amount of non-compliant code in the project, AI may follow the existing code style rather than the new rules. In this case, it is recommended to:
Clearly inform the model that the current task is “refactoring”.
In specific scenarios, require the AI to strictly follow the new rules.
Initiate a dedicated refactoring project to gradually improve the overall code quality.
