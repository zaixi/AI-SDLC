# 按内容选择视图

先确定读者要理解什么，再选择形式；不按行业或工作阶段套用固定图集。

| 内容 | 可用视图 | 表达重点 |
|---|---|---|
| 概念、组成与层级 | 分组图、树、概念关系图 | 包含、归属、关联；这些关系不自动表示调用或先后 |
| 步骤、分支与条件 | 流程图、伪代码 | 顺序、条件、分支和结束位置 |
| 参与者之间的交互 | 时序图 | 谁向谁发送什么，先后、等待与并行 |
| 随时间发生的观测 | 时间线 | 事件和时间；先后不自动代表因果 |
| 状态变化 | 状态图 | 状态、事件与转移条件；意图不自动表示完成 |
| 对象与数量关系 | 类图、实体关系图 | 关联及数量；沿用内容给出的概念或实现层次 |
| 方案或属性比较 | 并列视图、对比表 | 同一维度的差异，保留给定条件与未知 |
| 前后变化 | diff、同层次前后图 | 改动位置及理解所需的上下文 |
| 空间、界面或复杂概念 | SVG、HTML | 布局、位置、分组及交互；使用给定标签和数据 |

Mermaid按内容选择flowchart、sequenceDiagram、stateDiagram-v2、classDiagram或erDiagram；有合适渲染支持时也可用C4等其他图种。语法选择不能替代对原意的核对。

## 信息密度

一张图解释一个主要问题。必要时先总览再展开局部，沿用同一套术语。图和表同时使用时分别提供不同信息；正文补充原因或条件，但仅使用当前内容给出的解释。

详细内容不必全部画进图里。保留影响理解的条件、例外与边界，其他细节可用紧邻短文说明。
