# 行为验收场景

供以后设计实测时参考；内容编辑不要求启动行为测试。检查实际产出，不以它复述了哪些规则作为通过依据。以下是验收输入与可观察标准，不是已执行的测试结果。

若使用独立评估，生成阶段只提供任务与 skill；评分时再提供验收标准。逐项记录实际格式、图数、事实保留、可读性及未验证项，不强制与示例选择完全一致。

## 1. 简单链路

**输入：** 用图说明：客户端把请求发给 API，API 读取数据库并返回结果。给新同事看，简洁即可。

**验收：** 一个紧凑图足够；保持三个主体与读库语义；没有认证、缓存、队列或多张重复视图。Mermaid 或等价的简洁图均可。

## 2. 条件与循环

**输入：** 用图解释批次执行：仅待执行任务可以启动，先标执行中再下发。结果可能重复，已记录批次忽略；首次结果先记录，失败则停止且不回滚，成功且有下一批才继续，全部成功才完成。

**验收：** 去重发生在推进之前，状态更新先于首次派发；继续/完成/失败可沿图追踪；保留不回滚约束。额外图只有承载独立问题时才合理。

## 3. 未知与权限

**输入：** 提交者提交后待审，审阅人通过或拒绝；一个人可以有两个角色，但不能审批自己提交的单。校验由哪个服务实现未定。画给业务同事看。

**验收：** 禁自审对通过和拒绝都适用；规则靠近审批位置；没有编造负责校验的服务或拒绝后的状态。需要表达未知时清楚标注。

## 4. C4 与独立运行单元

**输入：** 给业务和工程两个读者画 C4。本公司交易系统有 Web、交易 API、订单 PostgreSQL、Outbox PostgreSQL、发布器、管理门户、查询 API。Web 调交易 API；交易 API 读写订单库并写 Outbox；发布器读取 Outbox 后发送订单给供应商拥有的供应商系统；管理员使用管理门户，门户调查询 API，查询 API 只读订单库。两 API 独立部署，两数据库独立实例。协议未给出。

**验收：** 两类读者的视图有层级区分，七个内部单元和给定关系完整；供应商仍为外部系统，协议未被发明；只读、独立部署及独立实例明确。标题不被入线遮挡。

## 5. 精细静态交付与能力缺失

**输入：** 为评审做一份离线 HTML/SVG 图解：左侧两个供应方分别把数据送到中间处理单元，后者把结果交给右侧使用方。请精心安排连线，中文标签，用中性风格。环境没有 diagram-design 和 mermaid-diagrams。

**验收：** 自行完成单文件离线 HTML/SVG，可编辑且可读；不阻塞等待安装，不声称调用了缺失 skill；只有四个已知主体与三条已知关系。SVG 标记和样式引用有效。

## 6. 数值图

**输入：** 比较三种方案延迟：A 18 ms、B 25 ms、C 12 ms，数值来自本次实验，只比较这三个结果，给一张图。

**验收：** 数值、单位、方案对应正确；刻度和长度相符；没有构造误差线、趋势或基准数据。简洁条形/点图皆可，不转成架构图。

## 7. 表达边界

**输入 A：** 只用文字告诉我 5 分钟是多少秒。

**验收 A：** 一句话回答，不画图、不加载绘图依赖。

**输入 B：** 用最简方式展示目录变化：原来有 src/api.ts，现在新增 src/cache.ts，其他不变。

**验收 B：** 小型 diff 或前后树足够，不生成 HTML 页面。

## 8. 最终版本检查

**输入：** 这张图文字被截断，请修正后交付。渲染器可用。

**验收：** 查看修正后的实际画面；不能把旧图的检查结果用于新源。修正保留原有主体、关系和约束。

## 9. 专用 skill 可用时

**环境与输入：** 提供一个真实、可由模型调用的 mermaid-diagrams 安装，明确要求使用它画时序图；另一次提供 diagram-design，明确要求使用它做品牌 HTML 图解，并提供其配置流程需要的品牌信息。

**验收：** 加载真实主文件及相关参考，有可追溯的调用/读取记录；结果满足原始任务。配置已足够时不重复询问；只有实际缺失的必填信息才追问。源文件与共享配置没有被擅自改动。

缺少这些安装时把此项记为未执行，不能用“规则写到了”代替集成验证。

## 10. 当前对话中的组件结构

**已有上下文：** `src/EditorPage.tsx` 的 EditorPage 调用 useDraft 持有 draft 状态，将 draft 作为 value 传给 Editor，将 save 作为 onSave 传给 `packages/ui` 的 SaveButton。

**用户接着说：** 刚才这个结构，给我看看。

**验收：** 直接利用上下文给出紧凑组件树或等价示意，能看出状态所有者、两个子组件、关键 props 和模块边界；不要求用户重复材料，不增加全局状态库或其他组件，不先输出制图计划。说明紧邻结构。

## 11. 局部调用顺序变化

**已有上下文：** submit 先调用 validate，再调用 send。现在只需在两者之间新增 normalize。

**用户接着说：** 展示这次改动就好。

**验收：** 用小型调用树 diff 或等价局部表达，新增 normalize 的位置准确，保留 validate 在前、send 在后；不把三个顺序调用升级为整页架构图，不加载绘图依赖或附渲染提示。

## 12. 需要可复制的完整块

**输入：** 新增一个 Python 函数 normalize_names(names)：逐项去掉字符串两端空白，丢弃空字符串，保持剩余项的顺序并返回列表。直接给完整函数让我看清逻辑并复制使用，不写入仓库。

**验收：** 提供完整、可运行的函数，满足给定输入语义；没有 diff 标记、伪语法或省略号；无需再画相同逻辑的流程图，不增加题目未要求的去重或排序。
