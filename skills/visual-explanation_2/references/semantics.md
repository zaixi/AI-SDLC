# 语义要点

仅阅读当前任务涉及的部分，也适用于承载相同规则的伪代码和表格。图种为含义服务，同一约束可用不同工具表达。

## 状态、条件与权限

- 状态图回答对象“处于什么状态，何时可以转换”；流程图回答“检查什么、接下来做什么”。把它们混用时，确保读者能分清状态与动作。
- 转换标签靠近对应边，用“角色／事件 [条件]”表达责任与守卫。长条件可放在紧邻规则中，由适用的转换明确引用。
- 保留条件中的“且/或/非”、数量和时间范围。“当前至多一个有效执行”只约束当前有效数量，不能改写成“曾经执行过就不能再执行”。
- 角色资格与身份限制分别表达；若规则禁止审批自己的提交，兼任角色也不能绕过该条件。共享限制覆盖它约束的所有操作，例如审批包含通过与拒绝时，禁自审适用于两者。
- 分支有可区分的条件和结果；默认分支、未知值处理与拒绝后的去向按材料表达。仅在已知终态使用终止符；材料未定的结果标为未定。

## 重复事件、循环与并发

- 区分对象状态、批次进度和事件处理；一个动作不必对应一个新状态。必要时用局部决策视图解释状态内部的处理。
- 保留去重的键、作用范围和有效时间：某批次、某对象、全局去重含义不同。材料未给出的范围保持未定。
- 检查资格、去重、记录结果、更新状态、派发或推进的顺序，按已知规则表达。异步调用、并发、重试和回滚都需要依据。
- 正常路径与影响结论的重复、失败、取消和返回路径可追踪；忽略重复事件与进入失败状态应可区分。

## 时序与角色交接

- 只有先后顺序本身重要时才选时序图。参与者、消息方向与同步/异步语义来自材料。
- 关键分支用 `alt`，可选行为用 `opt`，重复用 `loop`；只在已知并发时使用 `par`。复杂条件若使时序图难读，将判断移到有明确入口/出口的决策视图。
- 在图中表达处理顺序，避免仅把关键步骤写入角落文字框；必要的解释注释放在对应消息旁。
- 泳道按承担动作的角色或单元划分。角色权限与具体校验实现位置是两回事：只有材料明确时才能将校验放到某个服务。

## 架构、C4 与关系方向

- 组织边界表示归属，系统边界表示系统范围，部署边界表示运行方式；让标题清楚表达它们，避免仅靠颜色区分。
- C4 上下文显示人员、系统和系统间关系；容器视图展开目标系统的应用与数据存储，外部系统仍可作为系统级依赖出现。组件视图只在需要时展开某个容器。C4 容器不等同 Docker 容器。
- 区分类型与实例、逻辑模块与运行单元。同类型的独立实例仍是不同主体；总览可分组，但需要在相关明细中保留实例数量、归属及已知的独立部署关系。
- “调用/读取/写入”的箭头通常从发起方指向目标；“数据/事件传递”通常顺着信息方向。选择能回答当前问题的语义并说明，混合时由标签清楚区分。反向箭头必须有明确语义。
- API 读写数据库可以用一条标为“读/写”的访问关系；同端点的不同事件可以合并标签，但每一种已确认事件都要可见。
- 题目只说某人使用系统时，不擅自连到某个具体门户；只确认职责时，不推导未给出的调用、协议或基础设施。

## 关系模型、层级与比较

- ER 关系的两端基数都需要依据；未给主键、字段、可选性时，用概念实体关系表达，或直接标为未提供。
- 树适合单一父子关系；多重归属、交叉依赖或循环用图。调用树中的重复出现表示不同调用位置，不自动表示多个部署实例。
- 属性比较与角色权限优先矩阵。前后结构图应共享名称、语义配色与大致位置，使变化显眼；已经足够清楚的局部修改用 diff。
- 推测的因果与已观察的相关性区分标注；用因果箭头需要材料支持。

## 数据与时间

- 条形图用于量级比较，折线图用于有序趋势，散点图用于变量关系；“占比”须有明确整体，“流量带宽”须有数量守恒依据。
- 保留原值、单位、类别和时间范围。缺失值保留缺失；只有用户要求示意数据时才构造并标明示意。
- 刻度与视觉长度相符。比较绝对量的条形使用共同尺度和零基线；各自的“占限额比例”需要真实限额，不能替代绝对量比较。独立尺度的分面、截断轴、对数轴及聚合方式需要明确说明。
- 排期只画已知起止/依赖；相对顺序用时间线，不为凑 Gantt 图发明日期。
