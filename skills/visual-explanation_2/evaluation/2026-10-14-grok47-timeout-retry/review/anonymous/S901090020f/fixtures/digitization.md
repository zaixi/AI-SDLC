# 数字化平台：给定事实

以下是本题完整材料，不代表真实生产系统。传输协议、消息队列、重试调度方式均未确定。

## 内部单元（14 个）

| 区域 | 单元 | 职责 |
|---|---|---|
| 接入 | 上传页 | 供用户提交原件 |
| 接入 | 接收 API | 保存原件并建立作业 |
| 接入 | 原件库 | 保存原始文件 |
| 处理 | 作业表 | 保存作业状态 |
| 处理 | 调度器 | 找到待处理作业并派发 OCR |
| 处理 | OCR 工作者 | 识别原件并保存文本 |
| 处理 | 文本库 | 保存识别结果 |
| 检索 | 索引工作者 | 读取文本并更新搜索索引 |
| 检索 | 搜索索引 | 保存可查询的索引 |
| 检索 | 查询 API | 读取搜索索引 |
| 检索 | 搜索页 | 供用户检索 |
| 运维 | 状态页 | 供用户查看作业状态 |
| 运维 | 状态 API | 只读作业表 |
| 运维 | 通知器 | 找到已完成作业并调用外部邮件服务 |

“外部邮件服务”不属于平台。各内部单元均需在相应细节中保留，不能因职责相近而合并。部署方式没有提供。

## 已知关系和成功路径

1. 上传页把原件提交给接收 API。
2. 接收 API 先把原件写入原件库，再在作业表建立待处理作业。
3. 调度器从作业表读取待处理作业，先把状态改为处理中，再派发给 OCR 工作者。
4. OCR 工作者读取原件库，把识别结果写入文本库，再把作业表状态改为待索引，并通知索引工作者。
5. 索引工作者读取文本库，写入搜索索引，成功后把作业表状态改为已完成。
6. 搜索页调用查询 API，查询 API 只读搜索索引。
7. 状态页调用状态 API，状态 API 只读作业表。
8. 通知器从作业表读取已完成作业，调用外部邮件服务发送完成通知。

## 失败行为

- OCR 失败：由 OCR 工作者把作业表状态改为失败。再次处理需要人工重新排队，但人工操作入口尚未确定。
- 索引失败：作业保持待索引，只重试索引；已写入的文本保留，不重跑 OCR。重试由谁、何时调度尚未确定。
- 邮件发送失败：作业仍是已完成；通知器只重试邮件发送，不重跑 OCR 或索引。重试时机未定。

## 阅读目标

新同事需要成功主链和区域职责的总览；值班工程师需要定位各条失败路径及不受影响的部分。总览可以隐藏细节，但具体单元、读写方向、先后约束和失败规则须能在相应明细中找到。
