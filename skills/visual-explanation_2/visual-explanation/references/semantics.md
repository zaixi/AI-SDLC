# 语义要点

当简化表达可能改变条件、顺序、边界、关系或尺度时，查阅对应部分。以下要点也适用于伪代码、表格和 HTML；选择工具仍由主文件负责。

## 条件与事件

- 保留“且／或／非”、数量与时间范围，以及规则作用的对象和操作；角色资格不等于具体身份，当前数量不等于历史次数。
- 区分状态、动作与进度，按已知规则表达终态、默认分支及失败、取消、返回路径。去重保留键、范围与有效时间；忽略重复事件不等于执行失败。
- 保留影响结论的判断、记录、更新与派发顺序；先后发生、等待完成和并发执行分别表达。角色职责不自动确定校验所在的服务。

## 边界与关系

- 区分组织归属、系统范围和部署边界，以及类型、实例、逻辑模块与运行单元。分组后仍保留与问题有关的实例数量和独立部署关系；调用树中的重复出现不等于多个实例。
- 调用箭头从发起方指向目标，数据或事件箭头顺着信息方向；用标签或线型区分调用与数据返回，并单独表达同步／异步。读取请求指向数据源，读取结果指向接收方，同图中的约定保持一致。合并连线仍需保留相关关系。
- 分别核对关系两端的基数与可选性；若图形符号不能准确表达数量范围（如 1..2），在对应连线上标明范围或改用其他表达。概念关系不要求补造字段。多重归属、交叉依赖或循环不应被树形布局隐藏。

## 数据与时间

- 保留原值、单位、类别和时间范围，区分缺失值与零；占比须有明确整体，流量宽度须有数量依据。
- 比较绝对量的条形使用共同尺度和零基线；各自的占限额比例不能替代绝对量比较。独立尺度、截断轴、对数轴和聚合方式应明确说明，视觉长度与所标刻度相符。
- 排期只画已知起止与依赖；只有相对顺序时保留相对顺序。
