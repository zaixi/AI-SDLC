# 0.3.1：让图承载主要判断

本轮检查 0.3.0 是否把重要判断留在正文，以及如何让图帮助评审。结论是：缺资料题的新图更直接展示核实、验证与决策路径，但已知结构题旧版已经足够清楚；新版还出现一处正文职责错误。不能据此宣称新版全面更好。

[查看四份未改写的原始回答对照](comparison.md)。日期：2026-10-09。

## 改动与观察

- 按当前问题选择视图，不默认用模块总览回答风险、取舍或下一步问题。
- 把关键风险、条件或下一步放进图或紧邻批注。正文解释理由、依据及不适合画图的细节；不为图独立而把长文塞进节点。
- 已有明确调用关系时复用结构，在相关位置标测试缺口；未知调用关系仍不能补造。
- show-me 上游正文逐字保留，本地规则和按需指引分别维护。

| 题目 | 0.3.0 测试输出 | 0.3.1 测试输出及问题 |
|---|---|---|
| 05-scope：职责已知，缺幂等资料 | 图呈现职责及评审关注；正文说明先核实再验证/决策 | 图增加现有契约待核实和后续路径，信息更充分；正文却把审计也说成拥有状态，超出输入 |
| 06-existing：结构已知，缺测试证据 | 已把两个测试缺口标在计费旁，正文补验证方法 | 增加订单恢复验证连线，仍复用机制；客户端到网关的边未在输入中明确给出，最好省略或标为推断；没有证明这一版更易读 |

**05-scope 的错误不能忽略：**输入是“订单拥有订单状态，计费拥有扣款状态，审计记录结果”；新版正文写“订单、计费、审计的状态所有权已确定”。审计记录结果不代表它拥有状态。图内职责写对也不能抵消正文写错。原始输出保留，未用人工修正后的回答替换。

据此在最终 Skill 加入“逐项核对图和正文的主体、行为与所有权，不把记录、订阅或调用写成状态所有权”。同时修正指引：已有充分证据复用结论，缺证据才验证。这两处是回归后的规则补充，**没有独立生成复测，不能声称已经消除了错误**。`inputs/v031-final/` 保存相对测试快照变更的两个最终文件，`inputs/v031/` 保持生成时快照不变。

## 方法与验证边界

两版各由一个新 Agent 会话生成，两题在各自会话内连续回答。均使用 `fork_turns=none`，不继承主对话，仅按指令读取自己的 Skill/参考文件与相同题目；实际读取记录见 `outputs/*/provenance.json`。文件系统共享，读取限制由指令约束。主 Agent 按预先保存的 `criteria.json` 核对，不是盲评或用户可读性研究。

每题每版只有一次生成；没有重复采样、固定随机种子或第三方评分。本轮没有重跑 show-me 与 mermaid-diagrams，不能外推对它们的优劣。

四张 Mermaid 图通过 Mermaid 12.1.0 语法解析，**实际渲染未执行**。语法通过不能证明职责正确、布局清楚或阅读负担下降。客户端安装、自动匹配和委托调用也未测试。

含图源码的字符数：05-scope 为 629 → 639；06-existing 为 644 → 717。新版没有更短，图的信息更充分也有密度代价。下一步应优先用真实任务检查语义与阅读负担，避免继续堆规则。

`protocol.json` 记录会话与最终补充的区别；`metrics.json` 保存字符数和原始回答哈希；`syntax-results.json` 保存解析结果；`SHA256SUMS` 覆盖本轮资料。最终规则仍需真实任务验证。
