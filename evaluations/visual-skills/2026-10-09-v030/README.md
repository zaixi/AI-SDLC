# visual-explanation 0.3.0：关系与未知项回归

日期：2026-10-09。目标是修正“职责推导调用链”和“输入缺失全部变成待决定”，并减少无关的例行说明。

## 改动

- 图上的关系本身是断言：职责不能推出调用链，有向和无向实线都需依据。评审影响边须说清含义。
- 先核对已有机制，再区分待核实、待验证、待决策和建议；缺资料不等于缺机制。
- 已确认的方案直接复用，证据不足优先补验证；确认现有方案不足时才提出新的取舍。
- 同一机制的多个问题合并成关键缺口，附下一步动作；不把每个未知项交给人作决定。
- diff/伪代码不附未渲染提示，来源及过程状态尽量简短集中。show-me 正文逐字保留。

## 方法与限制

旧版0.2.0和新版0.3.0各由一个全新 Agent 会话生成三题回答，均使用 fork_turns=none，不继承主会话、不读取另一版本输出。相同题目、继承的默认模型与设置、相同工具限制。参考资料允许按各版本指针读取，实际读取见 provenance.json。

每会话连续回答三题，未做题间会话隔离、固定随机种子或重复多次；文件系统共享，读取限制通过指令规定。主Agent按预先保存的 criteria.json 审阅，不是盲评。这是针对已发现问题的小样本回归，不是统计性胜负结论。

原始输出没有被改写。生成阶段不联网、不安装、不渲染；之后统一运行 Mermaid 12.1.0 语法解析。没有测试自动调用、客户端兼容性或视觉布局。
