# 匿名输出比较评审

仅依据给定 prompts.json、rubric.json 与 30 份匿名回答。未搜索来源映射、未读其他资料、未联网；未修改回答。A/B/C 来源隐藏，每组两个独立 run、每 run 五题。这里是独立的内容审阅，没有虚构数值总评分。

## 关键覆盖与证据边界

29 份关键覆盖为 adequate，B-run2-05-scope 为 partial：它正确保留职责、重复扣款风险及幂等待验证，但把输入未提供的模块关系呈现为已知，未完全满足“区分事实、建议和未知项”。逐份判断、精确引文及理由见 review.json。

所有租约题都包含 A 在 0 秒领取、B 在 31 秒重领、A 在 35 秒提交被拒，且没有用提交拒绝推出只执行一次。回答均把重复外部副作用描述为可能，而非已发生事实。所有职责题正确表达 API 入队、Worker 消费写库、ADR 不允许 API 直写库，没有编造吞吐或故障隔离动机。所有改动题完整覆盖缓存命中返回、变化时写入及写后失效。

所有状态题覆盖取消请求不改变 running、Worker 停止确认后 cancelled、执行可能先完成进入 succeeded、queued 可取消、failed 可重新排队及 succeeded 重试未规定。不同回答在额外常规状态边的证据限定上有差异。

## A 的具体表现

两个 run 都明确区分事实与推断。A-run1-04-state 原文：“`queued → running`、`running → failed` 按状态含义推断。”A-run2 同样把“开始执行／执行失败”限定为状态名称推定。这些转移虽未在题目明确给出，但推断已经被标注，不计为编造既定规则。

影响边界题中，A-run1 使用需求到独立模块的待决定虚线；A-run2 虽画出 G→O→B→A 链形，但边标为“建议”或“待设计”，并明确“现有调用关系未提供”。因此不能把 A-run2 的链形与 B-run2 的已知关系声明混为一谈。

A 的两个影响边界回答更详尽：幂等键范围/期限、并发控制、外部支付保证、崩溃窗口都以建议或验证项限定。A-run1 原文“若存在外部支付方，还需确认它支持幂等或结果查询”，没有断言题目已存在外部支付方。这些内容有评审价值，未因较长而判低质量；但与“简短中文”要求相比文字负担更大。两个回答的围栏外正文约 284/303 字符，B 为 176/120，C 为 155/94。字符数仅辅助说明篇幅，不代表阅读时间或评分。

A 常附“来源/依据”“未渲染验证”，增加少量元信息。改动题用短 diff，直接突出条件返回和缓存失效；A-run1 另外解释写入失败未提供，谨慎但并非完成题目所必需。

## B 的具体表现

B-run1 五题简洁，影响边界图没有添加模块调用链，原文明确：“虚线表示影响评审范围，未声明现有调用链。”待决定问题覆盖同一支付识别、计费去重、超时结果核查和审计关联。

B-run2-05-scope 的实线有向边 `G[入口网关] --> O[订单模块：拥有订单状态]` 及无向边 `O --- B`、`O --- A`、`B --- A` 不由题目模块职责推出。尤其正文称“实线表示已知职责的关联，不指定调用顺序”，直接将新增关系作为已知。“不指定调用顺序”只能限制顺序解释，不能证明这些关系存在。这是明确的关系证据问题，比状态名推断的遗漏标注更严重；同时，该回答并未声称已经具备幂等保证。

B-run1-04-state 的 `running --> failed: 执行失败` 被正文限定为按状态名称理解的失败路径，但 `queued --> running: Worker开始执行` 没有同样限定。B-run2 的这两条常规边都未标推断。它们合理且没有破坏取消规则，属于低强度证据边界问题，不与虚构模块关系同级。

B 的改动题两次均用短 diff，文字解释紧凑。B-run1 以删除后重新加入 write 的形式呈现，B-run2 保留 write 并新增条件/失效；两者语义正确。

## C 的具体表现

C 两次影响边界题都将已知职责节点与待决定/验证问题分开，用虚线表示评审影响，并明确其不代表已有调用链或已定方案。C-run1 问“幂等键由谁生成、传递和保存？”，C-run2 问“去重由谁保证；并发重试如何保证只扣一次”，均未把待定方案画成现成保证。

C 两次改动题都用新旧并列流程图，清楚呈现分支，适合读者直接沿流程阅读。相比 A/B 的短 diff，源码节点和边更多，但正文仍短；实际渲染后的空间占用、易读性和阅读速度没有测试，不能单凭 Mermaid 比 diff 更长就认定选图不当。

C 两次状态图均把 `queued --> running: Worker 开始执行` 与 `running --> failed: 执行失败` 画成普通转移，未标注它们是按名称推断。与 B-run2 状态题相同，属于合理常规推断的限定不足，核心状态规则仍正确。C 对 succeeded 重试未知作了清楚说明。

## 选择图与文字负担

租约题的时序图、职责题的流程/职责边界图、状态题的状态图都与任务匹配。影响边界题用已知模块加待评审节点/边也合适；B-run2 的问题是实线关系被当作事实，不是所有关系图都不适用。

A/B 的 diff 更紧凑，C 的并列流程更展开；两种都能正确解释改动，没有充分证据判定唯一最优图种。A 的元信息及影响边界题更多具体建议构成额外阅读负担，也提供额外评审深度；该维度不等同内容正确性。

## 限制

每组仅两次会话、五个刻意选择的问题，只能报告本批输出差异，不能据此推广总体稳定性或归因于某种指引。没有来源映射，不能解释组别来源。此次只判断源码语义和文字负担；图语法由主 Agent 另检，实际渲染、布局、用户理解与自动触发均未测。29/1 是覆盖分类计数，不是总质量分数或排行榜。
