# visual-explanation 0.4.1 与 0.4.2：实际图片反馈比较

**结论：0.4.2 的产出可用，未显示相对 0.4.1 的明确整体优势。** 两版收到实际图片后都修复了布局问题，关键关系保留；新版检查规则值得保留，但不据此继续加规则。最终 15 张图通过语法解析和实际 SVG/PNG 渲染。

本轮每版两题、每题一条独立轨迹，共四条。每条保留初稿、第一次反馈后的修订稿、第二次反馈后的最终稿；三阶段属于同一条轨迹，不计为三次独立样本。

## 如何比较

复用上一轮的发布体系与跨组织 C4 两题，控制题目、模型 CLI、参考资料及渲染器一致，只替换主 Skill 的 0.4.1/0.4.2 文本。每个主 Skill、Mermaid 指引及所需参考全文注入，不测试客户端发现或主动加载。执行顺序在两题间反转，未设置随机种子。

每条轨迹使用新容器、新临时用户目录、新会话。容器只挂载本题输入、本题图片及只读登录凭据卷，不挂载仓库、其他输出、父会话或 Docker socket。反馈在本条会话中 resume，两次均附实际 PNG 与渲染状态，不给人工修图意见。生成器禁止调用其他工具，CLI 使用 read-only sandbox。

渲染由独立、无网络容器执行，Mermaid 12.1.0、CLI 12.0.0、Chromium 154.0.8037.92，提供中文字体。Chromium 采用 Puppeteer 的 --no-sandbox 容器配置；隔离由只读文件系统、只读输入、cap-drop ALL、no-new-privileges 及独立容器提供。浏览器不挂载登录卷。

两版都有相同的两次图片反馈机会。最终若改源码，再独立渲染，但不把第三轮图片交回模型。所有原始回答完整保留，没有人工修图或择优替换。

## 可审计资料

- `inputs/`：两版主 Skill、相同 Mermaid 指引、题目；上游原文及许可证随快照保留。
- `trajectories/<版本>/<题目>/stage0..2/`：原始回答、传入文本、CLI 事件、调用状态。
- 各轨迹的 `rendered/`、`render-inputs/`：原图、实际 SVG/PNG、渲染状态与可编辑源。
- `outputs/`：最终原始回答的逐字副本。
- `scripts/compare.py`：实际运行驱动；路径及登录状态卷来自本环境，需要按新环境准备 CLI、登录、Node、Docker 镜像和输入源。输出目录存在时拒绝覆盖。`render-package-lock.json` 固定渲染依赖，`render.Dockerfile` 固定浏览器基础镜像。凭据内容不入库。

## 解释边界

这是每题每版一条轨迹的小样本；评审由主 Agent 知道版本后执行，没有盲评或用户阅读实验。外部控制器提供图片，不证明 Agent 能自主发现或调用渲染器；也不覆盖 HTML、各客户端安装或其他领域。两版都有图片反馈，因此可以比较同条件产出，不能把全部改善归因于 0.4.2 的新增文字。
