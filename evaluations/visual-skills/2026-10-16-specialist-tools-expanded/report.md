# 扩展评测结果

本轮支持继续把 visual-explanation 作为通用入口。Archify 在复杂关系与角色流程上有补充价值，但还不适合作为默认架构后端；Fireworks 的静态 SVG 与导出能力有价值，自动路由路径的完成度仍不足。没有修改或安装任何正式 skill。

## 方法与限制

OpenCode 1.14.28 + deepseek-flash/high，4 题 × 3 组，每格一次，无重试与人工反馈。单题 1200 秒、96 请求、98304 输出 token（含 reasoning）、单次 32768；均为上轮的两倍。保留相同固定技能版本及依赖。生成包排除维护 AGENTS.md，V01 补挂原文文件。隔离检查全部通过，12 次真实运行均读取本组 SKILL.md，外部网络不可用，API 错误 0。

预算和隔离同时变化，不能把改善全部归因于加预算。模型只能读文本，不能看截图；主 Agent 在生成后打开产物并评审，非盲评。只测一次，结果不足以估计稳定胜率。V04 是适用范围探针，两种专业工具都明确不以统计图为定位，单独讨论。

9 次正常结束，3 次达到总输出预算并以 length 结束；没有时限退出。exit=0 或 has_text=true 不等于完成交付，尤其是中途会话摘要也会出现在 answer.md 中。

## 逐题结论

| 题目 | visual-explanation | Archify | Fireworks |
|---|---|---|---|
| V01 平台总览与故障 | 完整 HTML，最快；明细多，但失败影响过度推断、主图偏小 | 完整两份 HTML；含义较稳，状态图易查，本题更好 | 5 张 SVG，无 HTML；失败视图文字挤压，且有过度推断 |
| V02 双站文档插图 | SVG+PNG 完整，分区、读写与反向交互清楚，本题最好 | SVG+PNG 已有但未正常收尾；漏缓冲读取，额外假设补传机制 | 只有 JSON 与调试 SVG，无 PNG；标签位置容易误读方向 |
| V03 采购审批 | 图与下一步表清楚，但生成成本较高 | 泳道角色清楚，本题消耗最低；画面较高 | 单图紧凑、完整；金额副标题有小歧义 |
| V04 方案比较（范围探针） | 结论、表、按指标分图清楚，内容准确 | 计算正确；强套流程，数值被默认隐藏，不适合直接比较 | 自写 SVG 卡片紧凑可用；有少量多余假设 |

### V01：内容准确比多画几张更重要

Archify 保留 14 个内部单元、外部邮件服务和关键失败规则，把作业状态单独画成第二张图。架构画面中区域主要由下方卡片解释，分组仍可更明确，但没有把未知失败后果写成事实。

visual-explanation 实际使用 answer-me-with-html，交付 1600×3888 的六面板页面。两图、关系表、单元表适合核对，但总览节点偏小，内容重复。其失败表称 OCR 失败时“该作业没有识别文本”、索引失败时“搜索索引不更新”，原题没给失败阶段或原子性，不能推出这些确定结论。Fireworks 的失败 SVG 也出现同样推断，并且多个节点说明挤出框。

### V02：现有 diagram-design 已能提供有效补充

visual-explanation 调用 diagram-design，输出简洁的东站／中心／西站布局，站内缓冲双向读写、上报与补传反向关系均完整，SVG 和实际生成的 PNG 都已查看。

Archify 图面好看、导出文件存在，但两个缓冲库都只画“写入缓冲”。HTML 卡片把“依据补传请求从本站缓冲库取数补报”“上报同时写缓冲”当作已知机制，题目没有给出。Fireworks 卡在路由调试，_dbg.svg 不能当正式完成品；图中上报/补传的文字标签与相邻线高度错配，确实妨碍理解。

### V03：三者可用，没有必要只追求一种风格

Archify 的泳道帮助分清职责，Fireworks 的普通流程图最紧凑，visual-explanation 的下一步表对申请人有用。三者都保留退回重检、主管后财务、拒绝终止和收货结束。Fireworks 的判断边为“超过5000元”，节点副标题却为“5000元以上”，有边界措辞歧义；这不是流程整体错误。

### V04：工具适用边界要留在路由层

visual-explanation 使用 answer-me-with-html 和 Python 生成 SVG，把各指标分图；Fireworks 自写 SVG 信息图，再使用工具检查和导出，三方案卡片更紧凑。两者都正确算出仅 C 满足两项门槛、单位成本分母正确、保留单次试验限制。Fireworks 图中把自动处理写成“无人介入”、最终回复称 A“省心”，是小范围无依据补充。

Archify 把指标串成流程。费用、完成率与工时的数值写进 tag 后被渲染为 data-detail=fine，初始 opacity=0。浏览器文本提取仍能找到数值，截图却不可见，这解释了自动检查通过却不好读。下方卡片补足费用和完成率，但不能直接看出 80/20/35 工时。没有把这个现象写成新的低级强规则；它说明选错表达工具或字段会让有意义的信息消失。

## 集成建议

- **visual-explanation 保持通用入口。** 本轮完成度与总体消耗最好，现有 am／diagram-design 路由确实能产生收益，但 V01 的冗长和过度推断仍需使用时留意。
- **Archify 保留为按场景选用的候选。** 复杂关系加状态细节、角色泳道是本轮的有效场景。V02 说明它也会漏关系、加假设并在导出时耗尽预算，不能把“架构图”一概自动路由给它。
- **Fireworks 暂不加入自动默认路径。** 两个自写 SVG 的场景成功，两个走 JSON 路由的架构场景失败；说明直接 SVG + 检查/导出可能比强行使用生成器更实用，但样本不足以证明因果。适合有明确 SVG/导出诉求时手动试用。
