# 复杂图比较：show-me单独使用是否足够

每组两份输出，比较show-me单独使用、mermaid-diagrams单独使用、0.4.1配合Mermaid指引；共六个新会话，六份未改写原文。日期：2026-10-09。

[查看复杂时序与数量关系的原始对照](comparison.md)。

## 题目与条件

第一题要求支付时序保留并发重试/回调、至多两次只查询、首次成功的共享原子登记与一次通知、重复成功忽略以及迟到回调。第二题包含六个领域概念、六条数量关系和跨团队、唯一分派、停用资格保留历史等普通线条不能完整表达的约束。

这些是合成的已确认内容，任务只要求准确表达，不要求研究机制、重做设计或验证真实系统。复杂性不由Agent自行追加。

与上一轮不同，**show-me组只读取show-me和题目，禁止加载Mermaid指引**；其余两组可读取分配的指引及相应参考。这是有意设置的资源差异，用于回答“模型已有知识加show-me能否表达复杂内容”，不把它称为相同资料下的三组比较。

每个条件×题目各一个fork_turns=none新Agent，继承相同默认模型及推理设置；无模型覆盖、随机种子或采样控制。共享文件系统，以指令限制读取；逐题provenance记录读取范围。生成期间不联网、安装、渲染或使用子Agent。

## 解析与表达差异

| 条件 | 时序题字符数 | 数量题字符数 | 读取补充指引 | Mermaid语法 |

| visual-v041 | 1766 | 505 | 主动加载Mermaid及相应参考 | 2/2通过 |

六张图通过Mermaid12.1.0语法解析，未执行实际渲染。字符数包含图源码，仅用于观察表达负担，不是质量分。

show-me时序题已经使用par、loop、alt、opt与嵌套分支，说明模型不读取额外指引也能生成这些语法。它把重试后的迟到回调处理写在短文与可迟到的回调块中；另外两组另画重试结束后的迟到回调块，图内细节更多。数量题三组均选择普通关联类图，保留六条多重性，把跨关系约束放在短文中，没有通过增加组合关系暗示级联删除。

本轮没有因为复杂图而出现语法失败，不能外推到其他图种、更多参与者或不同模型，也不能由源码判断哪张图实际布局更清楚。

## 独立内容评审

评审只读取隐藏来源标签的六份回答、题目与生成前固定的准则。检查图文共同表达的条件，尤其关注并发下重复成功通知和未知结果是否错误重置已确认状态。主Agent再核对引句和来源哈希，不是双盲或用户可读性研究。

六份均被评为关键覆盖adequate，未发现实质语义错误。主Agent复核两处可能误读：show-me在并发回调块标“也可迟到”，并由短文说明重试结束后仍处理回调，不因为没有另画一个回调块就算漏掉；mermaid-diagrams稿的查询响应与paid状态通知是不同消息，不将成功响应误计为重复状态通知。

## 对“是否需要额外指引”的判断

**在本轮这两题中，模型已有知识加show-me已经能够表达复杂时序与数量关系。**不能把这个能力完全归因于show-me正文，也不能说所有复杂图都必须加载mermaid-diagrams。

额外指引组把迟到回调另画成块、使用更多显式消息和标签，提供了不同的细节安排，但没有展示出明确的正确性优势；长图也未必更易读。这不是“指引无用”的证明：本轮只用了时序图和类图，没有覆盖C4、其他图种、模型不熟悉的语法或真实布局问题。

因此将mermaid-diagrams视为可查阅的图种/语法参考更符合当前证据；是否必须加载、何时收益明显仍未证明。本轮不改0.4.1的执行规则或继续追加样本，后续规则调整应单独说明，而不是把这次测试结果写成普遍保证。
