# visual-explanation 0.4.2 与原版 show-me

**结论：show-me 的发布图更紧凑，0.4.2 对未提供的实现位置更忠实；复杂架构最终质量接近。** 最终 15 张图通过语法解析和实际 SVG/PNG 渲染。支持保留 show-me 主体及少量补充，不支持宣布一方全面胜出。

每组两题、每题一条独立生成轨迹，共四条。两次反馈使用实际图片，不提供人工修图提示。初稿、修订稿、最终稿保留为同一轨迹的三个阶段，不计成三个独立样本。此次两组全部重新生成，不复用上一轮 0.4.2 的回答。

## 输入与比较范围

- show-me：Humanlayer 固定提交 `ca7c8088db69e315a8b2deea43820270457f8f3c` 原文件，含 `disable-model-invocation: true` 元数据。本轮显式应用该文件，不测试自动触发。生成器输入和文件挂载中均没有 mermaid-diagrams。
- 0.4.2：当前 visual-explanation 原文，加用户指定来源的 mermaid-diagrams 固定快照及题目需要的参考文件。全文注入，不测试客户端原生发现或自动加载。
- 两组使用相同的发布体系、跨组织 C4 题目、CLI、渲染器和反馈文本。无随机种子；两题反转组别执行顺序。

这是“原版 show-me 单独用”与“0.4.2 按现有适配方式用”的比较。Mermaid 指引与本地补充同时变化，无法将差异单独归因于某条规则或指引。全程限定 Markdown/Mermaid 与必要短文、表格，未测试 HTML 分支或其他领域。

## 隔离与反馈

每条轨迹在新 Docker 容器、新临时用户目录、新会话中生成，只挂载本题输入、本题图片及只读登录卷。没有仓库、父会话、其他组输出或 Docker socket 挂载。CLI read-only sandbox，不调用其他工具；本条轨迹后续反馈 resume 自己的会话，不复用其他轨迹历史。

渲染在独立无网络容器中进行，Mermaid 12.1.0、CLI 12.0.0、Chromium 154.0.8037.92，提供中文字体。Chromium 使用 Puppeteer 的 --no-sandbox 容器配置；外层隔离为只读根目录、只读输入和工具、cap-drop ALL、no-new-privileges，浏览器无登录卷。

控制器回传初稿实际 PNG 和渲染状态；生成器修订后，再回传一次实际 PNG。两组反馈机会和措辞一致。若最终稿继续改图，则另行渲染但不再回传，检查其是否诚实区分已检查和未检查的源码。

因此本轮验证的是“拿到实际图片后能否改善交付”，不证明 Agent 会自行发现或调用渲染工具。两组均得到反馈，也不把全部修图收益归于 0.4.2。

## 保留的证据

`inputs/` 固定主 Skill、指引及题目；`trajectories/` 保存所有原始回答、提示、CLI 事件、可编辑源、SVG/PNG 与状态；`outputs/` 是最终回答的逐字副本。评审不修改回答或图片，不择优替换。

`scripts/compare.py` 是实际运行驱动，拒绝覆盖已存在输出目录；运行需要准备相应本地路径的 CLI、正常登录状态、Node、渲染依赖及 Docker 镜像。镜像及渲染锁文件保留在 scripts；凭据内容不入库。

每题每组一个样本，评审由知道组别的主 Agent 执行，没有盲评或用户阅读实验。图数少不直接等于更好；分别核对信息保留、关系、条件、画面可读性和交付表述。
