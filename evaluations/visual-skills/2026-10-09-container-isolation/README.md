## 模型调用的阻塞

独立 CLI 使用 `--no-daemon`、`--ephemeral` 和 `--ignore-user-config`，不恢复历史会话、不接入宿主执行服务。仅复用已有认证文件的只读挂载；不复制认证内容，不修改、提取或替换平台代理凭据。

模型接口返回 HTTP 401，CLI 报认证令牌无法刷新。已有云会话的认证文件存在、`login status` 能识别登录方式，都不能证明它能用于新的独立 CLI 请求。第一次尝试还缺少配套 `codex-code-mode-host`；复核脚本挂载该程序后再次检查。辅助服务亦有拒绝响应，后续需一并核实。

因此当前只完成了文件访问检查，**模型生成和模型本地工具执行尚未验证通过**。不能用主会话或共享文件系统 Agent 代替后，再把结果称为容器隔离测试。

## 如何复核

需要 Docker 和 Python 标准库。只验证文件访问，不需要模型认证：

```sh
python scripts/check-isolation.py --result /tmp/visual-file-check.json
```

验证已有 CLI 认证能否实际调用模型：

```sh
python scripts/check-isolation.py --model-smoke --result /tmp/visual-cli-check.json
```

脚本使用环境已有的 CLI 和认证位置；不会选择其他模型、关闭 CLI 沙箱或修改宿主权限。独立 CLI 的有效认证应通过其正常登录方式配置，不应把令牌粘贴到聊天或提交到仓库。脚本返回成功不代表模型检查成功，需查看结果中的 `model_smoke.status`；`cli_finished` 也只是进程成功退出，不能替代对工具轨迹的核对。
