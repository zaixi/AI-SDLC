# 0.4.1：两题通用视觉表达比较

每组仅两份回答，比较0.4.1、show-me和mermaid-diagrams；共六个独立会话、六份未改写回答。日期：2026-10-09。

[查看三组原始输出对照](comparison.md)。题目是图书馆借阅流程和课程报名状态，不涉及AI原生研发流程。

## 检查目标与条件

- 视觉表达是否保留主体、流程分支、前提、状态转换与未知政策，不独立增加领域规则。
- show-me与Mermaid指引是否仍能覆盖这些通用内容，0.4.1是否有明确内容优势或额外负担。
- 当可读取的mermaid-diagrams已提供时，0.4.1是否主动加载主指引及所需参考。

三组收到相同的可用补充指引说明：可读mermaid-diagrams，根据各自分配的Skill自行决定是否使用，不额外强制调用。0.4.1的读取要求来自它自己的规则；原版show-me也可以自行读取。因此show-me组测试的是以show-me为入口、允许使用相同环境资源的行为，不是禁止补充资料的纯正文对照。

每个“条件×题目”使用一个fork_turns=none新Agent，继承相同默认模型与推理设置；没有模型覆盖、固定种子或采样参数。每会话只回答一题，工具用于读取和保存，禁止联网、安装、渲染和子Agent。文件系统共享，读取范围由指令限定；实际读取见逐题provenance.json。

六张图通过Mermaid12.1.0语法解析。**没有实际渲染或布局检查。**原始0.4.1回答注明当时未检查语法/渲染，这是生成阶段的状态；之后主Agent统一解析，未改写原文。字符数含图源码，不是token数或质量评分。

本轮可确认0.4.1在已明确提供可读指引的条件下，两题都执行了主动加载规则；show-me也有一次自主读取。因此不能说show-me必定不会使用mermaid-diagrams，也不能从两次观察估计调用稳定性。

这测试的是**明确加载入口后读取本地补充指引**，不是客户端自动发现、原生嵌套Skill调用接口或安装兼容性测试。没有测试指引缺失/只能手动调用时的分支，也没有测试不同模型。

## 内容观察

三组借阅图都将直接申请与预约后申请接到同一个柜台核验，保留证件有效和额度未满两项条件。show-me把通知不等于借阅完成写在短文中；另外两组把该区别加入流程节点。预约优先级、通知期限与逾期规则均未补造。

三组状态图都保留名额分流、补位确认、付款成功和三条允许取消的转移；未知取消/退款和超时规则留在正文，没有擅自补成状态箭头。show-me使用原状态标识，另外两组增加中文标签。

0.4.1没有回到研发决策或知识管理流程，但也没有展示出明显的内容优势。报名题额外的中文标签、解释和检查状态说明使其更长；这些是表达取舍，不能据此认定更好或更差。

## 独立评审与归档

来源隐藏的独立评审只读取匿名原文、相同题目和预先固定的rubric，不知道条件映射。主Agent再核对引句与主要结论；不是双盲实验或用户阅读研究，不评分真实布局。

评审认为六份回答均充分覆盖要求，没有实质遗漏、错误转换或补造政策。主Agent检查了六个ID覆盖、原文哈希及内容对应关系；这个结论只适用于本轮题目，不作为成功率或质量总分。
