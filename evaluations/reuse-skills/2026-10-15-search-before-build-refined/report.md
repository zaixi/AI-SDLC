# search-before-build 再次修订：五题实测

这次修订带来了局部改善：附件方案更快收束、采用现有仓库，三份设计交付都缩短了；主动发现也找到新的相关候选。但关键错误仍在，执行器题的研究成本增加，不能认定整体质量已提高。

OpenCode 1.14.28 + deepseek-flash/high，新版五题各一次，全部交付，无预算耗尽或上游错误文件。与上一轮修改版作历史比较，未重跑旧版。隔离、预算、输入沿用上一轮；没有无 Skill 基线，非盲评。完整方法见 [README](README.md)，[原始输出对照页](/home/liyujiang/.codex/skill-evaluations/reuse/2026-10-15-search-before-build-refined-191910/gallery.html) 仅本机可用。

## 逐题审阅

**R01：保持正确复用。** 使用已有 encode_rows，没有再造 CSV 编码器；独立检查覆盖逗号、引号、换行、生成器、空输入与 Unicode。现有测试加本轮新增测试共五个通过。没有观察到外部搜索，这符合小型适配任务的实际需要，但不能据此宣称每题都执行了 GitHub 搜索。

**R02：功能通过，未变简洁。** 使用 zipfile；递归、相对路径、符号链接、Unicode、输出位于源目录及已有输出的检查全部通过。代码从 3,238 增至 4,408 字符，还支持 SOURCE 为单文件，超出题目“SOURCE 里的文件”的主要需求。没有把这些额外能力算作质量加分。

**R03：说明缩短，关键接入错误仍在。** 推荐 lychee 与官方 Action，保留本地及外部链接检查、排除规则和磁盘缓存。但 CI 仍使用 github.sha 作为缓存键，同一提交定时重跑时无法保存更新后的缓存；[actions/cache 官方说明](https://github.com/actions/cache/blob/v4/tips-and-workarounds.md#update-a-cache) 明确要求新的唯一 key 才能保存更新。该问题连续出现，泛化的“核对关键假设”指令未纠正它。

另一个推理问题是：文档把 linkinator 的持久缓存列为未核实，却又称即使这些未核实项成立，它仍缺缓存。需要区分“当前证据不足以优先推荐”和“确认没有能力”。没有执行生成的 GitHub Actions。

**A01：主动发现有新收益，但不等于推荐合理。** 找到 adewale/skill-eval-harness 与 UiPath/coder_eval，推荐前者作为比较/报告层，保留本地执行层适配。前者官方确有[外部 runner 输出契约与配对评测](https://github.com/adewale/skill-eval-harness)，因此是相关发现，不是虚构候选。新版也承认 promptfoo 可以驱动 agent，改掉了上轮一概排除的说法。

但它没有充分比较“只抽取公共执行模块与配置”是否已能解决脚本复制问题，直接把配对统计、触发矩阵、CI gate 等纳入迁移阶段；这些能力有用，并不自动成为当前必需。文档还把 answer-key 泄漏检查与文件/网络隔离要求混为一类收益。

仍称 Inspect 需要自写 OpenCode agent，遗漏已有的 [Inspect SWE OpenCode 集成](https://meridianlabs-ai.github.io/inspect_swe/opencode.html)。这不证明 Inspect 应胜出，却削弱了排除它的依据。上轮错误的 forward_generation_config 调用本轮未出现，但本轮不再提供该代码示例，不能把“没再写”当成“已核实修正”。没有实际安装或迁移候选。

**A02：方案边界改善最明显，校验流程仍有错。** 从默认另建附件仓改为现有公共仓库 Releases，DOI/对象存储留作有需求时再考虑。研究与交付时间明显减少。不过仍提出索引、manifest、SHA256SUMS、打包/校验脚本等多份约定，未完全证明每份的必要性。

下载示例只取单个 session 附件和覆盖整批附件的 SHA256SUMS，随后运行 sha256sum -c SHA256SUMS，会因其余附件缺失而失败。用临时两文件清单、仅保留一个附件复现，退出码为 1。此问题与上轮一致。

文档一处称 Releases 解决历史对象造成的克隆负担，后文又正确说明历史不变，存在表达冲突；Releases 只能避免新附件继续进入 Git 历史。未发现上轮“immutable release 绝不可撤”的同样断言；没有进行真实发布。

## 判断

- 保留主动发现：成立，A01 找到了更贴题的候选。
- 减少过度研究：部分成立，A02 明显收束，A01 反而增长。
- 缩短交付：本轮三份设计都缩短，但重复与方案扩张尚未消除。
- 改善正确性：没有足够证据；缓存、单附件校验与候选能力判断仍有错误。

建议暂时保留当前版，不再按这五道题逐条补规则。它可以引导发现与取舍，不能替代具体集成验证。这些 case 已被用来指导修订，本轮属于回归检查，不能证明对未见任务的泛化提升；若继续判断是否值得保留新增指令，下一轮应采用未参与修改的新题或更换模型，而不是反复调这几道题。

本轮只评测与记录，没有继续修改 Skill。完整计量与两道实现题验证分别见 [metrics.json](metrics.json)、[behavior-checks.json](behavior-checks.json)。
