# 运行前固定的评审标准

两个真实问题，三个 skill，每题每组一次。不预选厂商或框架，不奖励引用数量、篇幅、图数量或模板合规。先评需求保留与方案能否落地，再看证据、取舍、范围、表达与成本。非盲评，单样本，无无-skill组，不推出稳定胜率。

## A01 实际评测执行器

- 理解被测对象是 OpenCode/coding-agent 工具轨迹；直接调用 LLM provider 的 prompt eval 不自动等同于测 agent。
- 能从所给 run.py 的覆盖关系理解实际使用路径；不把 relay_base 的未调用旧代码误认为当前实现。
- 保留每次 HOME/文件/输入/工作区隔离与凭据边界；不要把修改 prompt、换临时目录或框架默认断言等同于完整隔离。
- 模型、工具、references、subagents、压缩、联网/离线、渲染与反馈、超时/预算/重试、产物与指标有清晰归属。原有可用功能不能因引入框架而丢失。
- 明确现成框架具体替代什么、仍要保留什么适配代码及维护责任。允许保留现状/小步整理，只要与采用方案公平比较。
- 决策关键能力有一手证据，未确认的扩展点不能声称开箱即用。无需执行框架，但应给可检验的小型 PoC 成功/失败条件。
- 迁移可回退，避免先重写全部；未知团队/频率不虚构成分布式平台需求。

## A02 实际附件架构

- 区分 Git 当前树、历史对象、LFS/释放附件/对象存储/CI临时产物等实际存储性质；不把删除文件说成缩小历史，不把 CI cache 当永久归档。
- 用户可获取单次评测，不被迫下载整个仓库。报告/方法/必要小输入与原始大附件的边界明确。
- 能关联 protocol、来源版本、哈希、依赖信息和原始产物；版本与校验可追溯。匿名访问、保留期、文件限制与费用的关键主张需要实际资料支撑。
- 不把维护者本地路径或未上传的材料称为已发布；方案区分提议、发布、下载校验后的可用状态。
- 发布前筛选敏感上下文；凭据不随原始包发布。生成HTML的查看与执行/托管风险有合理处理，不能强迫浏览器执行才能查报告。
- 不强推或默认重写公共历史，保留现有历史链接的解释与迁移路径；不扩展到清理 materials/。
- 给简单可实施的写入/读取流程、失败恢复/校验和切换触发条件，避免为未知规模搭建服务平台。

## 记录

每题分别写：需求保留、关键错误/未证实主张、证据、可实施性、范围和表达负担。成本单列 wall time、模型请求、输入/输出 token（含子agent和压缩）与产物字符数。质量审阅不按总分硬算排名。
HTTP/模型服务失败、预算停止、质量错误分别记录。没有给生成模型 rubric 或前轮答案；只提供对应 skill 运行包、真实需求及脱敏代码/材料。
