# 范围控制：从设计文本改为实际实现

本轮支持继续使用当前修订版 AGENTS.md，暂不再加规则或叠加 Skill。修订版改动更小，预设行为检查全部通过；但原版也没有明显的功能扩张，不能证明新增规则稳定解决了“多做”。

两个可运行 Python 小仓库：账单导入修复、一次性日志汇总。原版与修订版各做一次，共四次实现。模型均为 OpenCode 1.14.28 + deepseek-flash/high；各组独立离线沙箱，无其他 Skill、旧答案或验收测试。题目来自先前设计题的改编，不是新发现的真实业务任务。方法与可复跑材料见 [README](README.md)。

## 范围有没有收住

**两组都基本收住了。** 没有新增 CLI 参数、第三方依赖、插件框架、持续运行服务或额外运维平台。两组账单都只重试 503，没有复现之前设计文本中的多状态码/网络错误重试扩张。

原版账单额外支持空库自动建表，增加统计返回值、细分异常类型和通用索引检测；修订版直接针对现有表迁移，没有这些扩展。它们增加了一些实现与维护面，但不足以称为严重过度设计。原版会拒绝非有限金额，而修订版遗漏这项判断，说明代码更少不必然更好。

事务、唯一索引、历史重复合并、SQLite 写锁及等待时限都是当前可靠性需求的一部分。日志输出的临时文件替换用于避免半成品及支持输入输出同路径，也不算多做。小型内部函数、必要测试和题目要求的迁移说明同样不算范围扩张。

## 预设测试通过之外的问题

冻结检查验证了批次回滚、金额与日期冲突、正常重跑、精度保持、唯一约束、重叠导入、历史重复和 503 有限重试；日志检查覆盖聚合、排序、CSV 转义、无效输入保留旧输出及同路径处理。所有检查通过，只能说明这些样本通过。

读代码后又发现三个具体问题，并用隔离临时数据复现。它们单独记录在 [diagnostics.json](diagnostics.json)，没有回改正式检查，也没有重跑生成：

1. **原版历史迁移比较口径不一致。** 正常导入用 Decimal 数值比较，但历史重复迁移把 Decimal 转回字符串再比较，因而将 `12.30` 和 `12.3` 视为冲突，拒绝迁移。数据被保留，没有误删；问题是阻止了数值一致记录的安全合并。修订版正确合并。
2. **原版给日志平均值额外规定两位小数。** 输入耗时 `[1, 2, 2]` 输出 `1.67`，修订版输出 `1.6666666666666667`。任务没有要求两位精度，原版作了未经说明的精度选择。冻结测试使用整数平均值，没暴露它。
3. **修订版接受 NaN 金额。** Decimal 可解析该值，代码没有检查有限性，会写入 `NaN`。原版明确拒绝。本题前提是正常十进制账单文本，未要求全面的畸形金额处理，因此这作为输入鲁棒性缺口记录，不混入预设验收通过率；也不据此认定由新增规则造成。

本轮没有复现上一轮强制金额保留两位的问题，但两轮输入不同：这次有真实 schema，amount 明确为 TEXT，README 明确无固定标度。不能把改善单独归因于规则；提供具体代码和存储语义本身也可能减少模型臆测。

## 当前结论

- 当前修订版在本轮实现中没有为简化牺牲主要需求，改动也更克制，值得保留。
- 原版同样基本守住范围；四个样本不足以证明规则有稳定增益。
- 本轮没有测试 SDK 第三方扩展、其他语言或其他模型，不能推出所有设计任务都适用。
- 范围控制与正确性要分别验证。增加通用口号不能替代具体语义检查，也不应把每个反例写进全局规则。

因此暂不创建或安装 scope-discipline/boring-engineering，不继续修改 AGENTS.md。后续在真实任务中积累证据；若同类扩张跨任务反复出现，再定位指令原因。已有题用于回归，下一次比较应补充未参与修改的任务及必要扩展场景。
