# Humanizer

采用 [blader/humanizer](https://github.com/blader/humanizer) 3.1.0，处理套话、重复解释、夸大和机械句式，保留事实、条件与必要的不确定性。中文效果尚未实测，不以缩短字数作为唯一目标。

## 安装和使用

将本目录安装到客户端支持的 Skill 位置。运行文件为 SKILL.md、LICENSE 和 agents/openai.yaml；最后一个文件仅供支持它的客户端使用，不是其他 Agent 的依赖。实际调用语法和自动匹配取决于客户端，不能仅凭仓库内存在此目录就声称已全局生效。

直接编辑文本时可调用 `$humanizer`，并说明「只返回最终文本」。上游直接粘贴文本的默认模式会返回草稿、问题清单和最终稿。

在上层任务或未来统一入口中使用上游的 Embedded mode：

> 使用 humanizer 的 Embedded mode 整理本次面向人的回答，只交付最终文本，保留事实、数字、约束、来源和不确定性。

这条是调用约定，未改写上游规则。当前仓库尚未实现统一调度入口，也没有为各客户端设置常驻调用；不要求用户以后手动记住多个 Skill。构建统一入口时由其选择本 Skill。

图解任务继续由 visual-explanation 负责；humanizer 处理随附文字。代码、命令、标识符和图源不作为普通文案改写。长文确有必要时保留篇幅，不强行套字数限制。

## 上游和更新

运行文件按 [upstream.json](upstream.json) 固定来源与 SHA-256，保持逐字一致。当前固定提交为 [225a6f3](https://github.com/blader/humanizer/tree/225a6f39ac85f76ee48dbad772ea4abe4ed6c9d8)。本地说明和来源记录不是运行规则，不复制维护上游的整套插件和第三方材料。

更新时先在仓库外获取上游，检查 SKILL.md 行为变更、许可证、所需资源和客户端配置。确认后同步上述三个文件；若新版新增运行依赖，一并纳入并记录哈希。随后更新 upstream.json，核对差异与包结构。不要自动追踪 main 覆盖已验证版本。

本次只完成来源、哈希、元数据与安装文件检查，未做模型生成对照、中文效果或客户端原生发现测试。后续按真实问题选 2–3 个案例，检查是否删除套话和重复、是否保留关键事实及限制，再判断效果；原始产物遵循 evaluations/ 的存储规则。
