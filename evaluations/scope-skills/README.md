# 范围控制研究与当前决定

目标是让 agent 在设计和实现阶段完成必要工作，减少没有当前依据的功能、配置、抽象和恢复分支。

2026-10-15 最终决定：经用户确认，已从 `~/.codex/AGENTS.md` 删除完整的 `### Design scope` 段，保留原有 Simplicity、Surgical changes 和 Verification；没有新增替代段落，也没有安装 boring-engineering 或创建 scope-discipline。随后迁入全局文件的输出表达规则属于另一项工作，不属于这些评测条件。

依据是新增六条规则与既有规则重复，几轮测试没有显示稳定、明显的额外收益，而不是证明它在所有任务中都无效。各轮报告描述测试完成时的状态，其中“全局文件尚未修改”是历史事实；当前决定以本页为准。

1. [现成 Skill 与原有规则比较](2026-10-15-design/report.md)：boring-engineering、karpathy-guidelines、微软 yagni、无 Skill，随后加入原 AGENTS.md；三道设计题。

3. [实际实现测试](2026-10-15-execution/report.md)：两个可运行夹具，原版与修订版；主要行为检查通过，仍有独立复核发现的缺陷。
4. [只删除 Design scope 的对照](2026-10-15-design-scope-ablation/report.md)：三个新构造夹具、两组唯一差异为该段；两组均通过检查且基本守住范围，未见明显增益。

## 下次继续

优先从真实任务中收集反复出现的范围扩张证据，再决定是否调整。已有题作为回归集；若要评估泛化，使用未参与修改的任务，并保留必要扩展、兼容性与可靠性需求。不要用代码行数或回答长短代替正确性和维护成本判断。

最近两轮的 inputs/rules.json 保存两组完整规则，scripts/prepare.py 可恢复到新的仓库外目录；具体运行步骤见各轮 README。早期两轮的外部 Skill 来源和固定提交记录在 protocol.json，原始快照仍在对应本机目录。重新获取时核对内容哈希，不能把当前 main 当作历史版本。

所有结论受单模型、小样本、非盲评限制；实现题是人工夹具，尚非生产仓库观测。完整请求、回答、产出、日志和依赖继续保存在仓库外，目前尚未公共归档。Git 中的报告、输入、协议和脚本用于接续研究，不能替代未归档的原始证据。
