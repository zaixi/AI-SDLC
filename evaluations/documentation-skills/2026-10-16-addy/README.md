# Addy 文档维护 Skill：案例与规则核对

日期：2026-10-16。状态：**独立生成测试已完成，尚未采用该 Skill。** 结果见 [比较报告](report.md)，配置见 [protocol.json](protocol.json)，逐轨迹摘要见 [metrics.json](metrics.json)。

## 评测范围

检验 `documentation-and-adrs` 能否在变更后识别并维护受影响的现有文档。固定来源与哈希见 [source.json](source.json)，输入见 [cases.json](cases.json)。不测试完整 Addy 流程，也不据此宣称 Matt 接入已有效。

比较组：相同模型、预算、工具和输入下，无额外 Skill 与显式加载 Addy 原文。每题每组两轮独立运行；第二题的 followup 属于同一轮轨迹，不计作独立样本。先测原文，不添加为本题定制的同步规则。仅提供当前题输入和本组 Skill，不提供评分标准、其他组答案或本项目讨论历史。

输出是文档修改提案，不是实际仓库工具编辑，因此即使通过，也只支持内容能力判断。自动触发、仓库检索覆盖及跨客户端接入另行验证。原始请求与输出放仓库外，报告保存摘要与证据位置；临时目录不当作长期归档。

## 案例和预先固定的判据

| 案例 | 应做到 | 关键失败 |
|---|---|---|
| 01 异步导出 | 同步更新 API 说明与架构图，保留未变的索引；状态码、任务标识和下载条件与批准决定一致 | 只更新文字漏掉图；继续声称同步返回下载地址；虚构任务实现细节 |
| 02 支付决定冲突 | 第一阶段指出未经批准的非幂等重试与旧决定冲突，不把现行文档改成新代码；补充批准决定后保留旧 ADR，新增替代记录并更新现行说明，指出窗口和稳定键仍未验证 | 把错误代码当作新约定；静默覆盖旧理由；声称仅凭传入 key 就保证不会重复扣款 |
| 03 内部重构 | 判断公开契约与原决定未改变，无需文档修改 | 为满足模板补建 Wiki、ADR 或无关说明；修改正确契约 |

每个判据记录通过、失败或证据不足，并引用产物。不能以输出长短、文档数量或表面完整程度评分。原作者评审属非盲评；两次重复只能提供初步观察，不报告稳定胜率。

## 已完成的规则核对

原文明确覆盖公共 API、用户可见行为与重要架构决定变化；要求沿用已有 ADR 位置和格式，改变决定时新增 ADR 并关联旧记录。它要求文案与代码和决定背景核对，不凭空强化保证。这些是适配本需求的依据。

但原文没有完整的“从 diff 找到全部受影响现有文档”的步骤，没有专门规定图文同步，也没有程序化覆盖检查。其 README、API 文档等默认检查清单可能导致范围扩张。第二题的复杂冲突能否处理正确不能从“保留 ADR”条款直接推出。

因此当前判断是：值得测试的文档维护指引，不能宣称已经解决文档漂移；也不能因规则没有明写就断言模型必然失败。

## 复现

使用有效认证的 Codex CLI，下载 source.json 固定提交的 Skill 文件；运行脚本会核对 SHA-256。指定新的仓库外空目录，不复用旧输出：

```bash
python scripts/run.py --output /tmp/doc-sync-new-run --skill /path/to/pinned/SKILL.md
```

脚本使用独立临时会话、忽略用户配置，并在输入中显式禁用工具。它不是容器级隔离；共享 CLI 内置指令，认证和运行环境仍来自宿主。支付后续阶段通过新会话携带首轮输入及回答模拟接续。评审标准仅供运行后评阅，不进入生成提示。
