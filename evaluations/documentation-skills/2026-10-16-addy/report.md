# Addy 文档维护能力：与无额外 Skill 基线比较

2026-10-16。本轮未观察到采用 `documentation-and-adrs` 的额外收益，暂不据此接入。两组都满足三题的核心判据，但这不证明已解决真实仓库中的文档漂移。

## 方法

模型 gpt-6.1-sol，推理预算 medium，Codex CLI 0.159.0-alpha.3。三题 × 两组 × 两轮，共 12 条轨迹；支付题有两阶段，共 16 次模型生成，全部成功。两组区别仅为是否在输入中附加固定版本 Addy Skill 原文。配置、来源、输入和脚本见 [README](README.md)。

每次调用独立 ephemeral 会话及工作目录，忽略用户配置；不提供本项目讨论、其他组答案或评分标准。没有观测到工具调用。共享 CLI 内置指令与宿主认证，不是完全独立容器；支付题第二阶段由新会话携带原输入、上一回答与新增材料模拟接续。非盲评，由案例编写者对照预先固定的核心判据阅读全部输出。

本轮是显式提醒“检查文档”的闭卷内容测试，不是原生 Skill 自动发现、真实文件编辑、仓库检索测试，也不是 Matt 与 Matt+Addy 的整条流程对照。Mermaid 仅人工检查内容，没有渲染验证。

## 结果

| 案例 | 无额外 Skill | Addy | 观察 |
|---|---|---|---|
| 异步导出 | 2/2 满足核心判据 | 2/2 满足核心判据 | 都更新 API 说明与图，保留有效 README 入口；202、job_id、succeeded 下载条件一致 |
| 支付决定冲突及后续批准 | 2/2 满足核心判据 | 2/2 满足核心判据 | 都先指出未经批准的重试冲突；批准后新增 ADR、保留旧理由、更新现行说明，并保留窗口及稳定键未验证结论 |
| 纯内部重构 | 2/2 满足核心判据 | 2/2 满足核心判据 | 都判断无需文档修改，没有补建无关 Wiki 或 ADR |

“满足核心判据”不是全文无误或稳定成功率。两组的导出图有些输出加入了 Queue 到 Worker 的调度关系，虽合理但输入未直接给出该关系；基线第一轮支付后续答案还补充了“不重新计算窗口”等表述。这些属于关系/规则推导边界，不能把所有细节当作实现事实。

全部生成内容的字符数（Python len，含 Markdown）：基线 4,883，Addy 6,173，约增加 26%。这是篇幅观察，不是 token 成本，也不用于判定正确性。

## 可核对的输出片段

- 基线支付第一轮第一阶段：“本次变更与已接受的 ADR-0001 冲突，应阻塞，不能通过修改文档将自动重试描述为已获认可的行为。”
- Addy 支付第一轮第二阶段：“新决定已批准，可以更新文档；但代码尚未证明键的稳定保存及 24 小时窗口约束，实现验收仍有阻塞。”该答案新增 ADR-0002，并将旧 ADR 标为被替代而保留正文。
- 基线内部重构第二轮：“本次仅调整内部实现，无需补充实现细节或新增文档。”
- Addy 内部重构第二轮：“本次仅简化私有实现，公开行为未改变，无需新增 API 文档或变更日志。”

逐答案路径、哈希和运行摘要见 [metrics.json](metrics.json)。完整生成日志及答案位于 `/tmp/doc-sync-eval-20261016-valid/`，未发布持久附件；这些路径只对当前环境有效，不能声称原始证据已长期归档。仓库只保存轻量方法、输入、摘要和报告。

## 为什么暂时不能据此采用

本轮把相关文件全部交给了模型，并明确要求检查文档；支付题还直接告诉它关键约束未验证。这能发现基本错误，却使“识别哪些文档受影响”与“是否主动触发维护”几乎不需要探索。因此两组表现一致，既不能证明 Skill 没用，也不能证明 Skill 解决了漏更新。

下一步更有区分度的测试应使用小型真实文件仓库：只下达功能修改请求，不额外提醒文档；让相关契约、设计图、历史 ADR 分散在既有目录，保留不受影响的干扰文档。比较是否找到该更新的内容、是否正确保留历史，以及是否无谓扩写。另设显式调用组，区分“能力有效但未触发”和“触发了仍没处理”。这属于下一轮建议，尚未执行，也未获准采用新 Skill。
