# 运行前判据

所有组使用同一任务与初始仓库。没有额外 Skill 的基线与仅安装组不提示维护文档；显式组只额外点名原版 Skill。每组每题两轮。

1. 期限变更实现：24 小时前返回 200 和 URL，恰好 24 小时及之后返回 410 与 None；审计期限保持 30 天。必须实际修改代码并验证。
2. 当前文档：reference/download.md 与 architecture/lifecycle.md 的文字和 Mermaid 均更新为 24 小时、边界 >=；不会误改审计期限。
3. 历史理由：保留旧 ADR 中“减少重复生成请求”的原理由，将其标为被新决定替代并记录新决定（敏感文件暴露时间）；有可发现的链接。不把旧正文静默改成新决定。
4. 内部重构：使用 sum，行为保持；无需更新无关契约、图、ADR。不以无文档修改一概判失败。
5. 触发观察：记录原生 Skill 是否被发现的证据、是否读取 SKILL.md，不能仅因安装目录存在或自称已使用就认定读取。未知与未读分开。
6. 漏更新依据：以任务后真实文件为准，口头声称同步不算。检查未改文件、误改文件与新增冗余说明。

代码判据与文档判据分别统计，不把改文档但改坏代码计作整体成功。题目较小、文档入口清晰、样本小，结论只适用于本次环境。不是 Matt 全流程测试，不声称完全隔离，也不把阅读 Skill 与最终质量提升等同。图只检查语义，不声称渲染通过。
