# 只要求改功能时，会不会主动维护文档？

2026-10-16。两题、三组、各两轮，共 12 条有效轨迹已完成。**本轮没有复现“代码改了、当前说明和图没更新”；观察到的差异是 ADR 历史处理：基线有一轮直接改写旧决定，两个 Addy 组均建立了替代记录。** 这是小样本观察，不能证明 Addy 已可靠解决文档漂移。

## 场景与方法

期限变更题只要求把下载可用期限从 7 天改为 24 小时，在精确到期时返回 410，保留 30 天审计期限并验证；没有提醒更新文档。契约、架构图、ADR 分散在 docs/reference、docs/architecture、docs/decisions，README 经 docs/index.md 指向它们。另一题仅要求把私有求和循环改为 sum，检查是否产生无谓文档维护。

| 组 | 输入差异 |
|---|---|
| 无额外 Skill | 原始仓库与功能修改任务 |
| 仅安装 Addy | 另在 `.agents/skills/documentation-and-adrs/SKILL.md` 放固定上游原文，任务不点名 |
| 显式调用 Addy | 与仅安装组相同，并要求使用 `$documentation-and-adrs` |

模型 gpt-6.1-sol，medium；Codex CLI 0.159.0-alpha.3。每次独立 Git 仓库和临时 CLI 会话，真实编辑文件、运行测试。忽略用户配置，但共享 CLI 内置指令及宿主认证，不是容器级隔离。没有把评分标准、本项目讨论或其他组答案交给生成模型。不是 Matt 与 Matt+Addy 的流程对照。

首次因额度不足仅完成一条基线轨迹。额度恢复后，在新目录从初始 fixture 重跑其余 11 条，保留首条结果及所有失败日志，没有按质量择优。共 23 次尝试、12 条有效完成，失败不计作 Skill 质量失败。详见[中断记录](interrupted.md)和[首次运行摘要](attempts.json)。

## 结果

每格分母为该题该组两轮。检查真实文件，而非仅采信最终回答。

| 判据 | 无额外 Skill | 仅安装 Addy | 显式调用 Addy |
|---|---|---|---|
| 期限变更：代码、精确边界和审计期限正确 | 2/2 | 2/2 | 2/2 |
| 主动更新下载契约 | 2/2 | 2/2 | 2/2 |
| 主动更新架构文字及 Mermaid 条件 | 2/2 | 2/2 | 2/2 |
| 保留旧 ADR，新增决定并建立替代关系 | 1/2 | 2/2 | 2/2 |
| 内部重构：实现正确且不改无关文档 | 2/2 | 2/2 | 2/2 |

12 个产物的项目测试及独立行为检查全部通过。期限变更产物各有 6 项测试，内部重构各有 4 项。外部检查另验证 86,399 / 86,400 / 86,401 秒、整数求和、空列表、审计期限，防止只依赖生成者自己的测试。Mermaid 检查内容一致性，未渲染。

### ADR 差异的具体证据

基线第一轮把 `ADR-0001 Seven-day artifact retention` 改为 `ADR-0001 24-hour artifact retention`，继续保留 Accepted 状态，在同一正文中混合原理由和新决定；没有创建新记录或替代链接。原先“为减少重复生成请求而保留七天”的理由仍有文字保留，因此不能说历史全部丢失，但未满足本轮独立历史决定及替代关系的判据。

基线第二轮及四个 Addy 产物均保留旧 ADR 标题、原理由，修改状态为被 ADR-0002 替代，创建新 ADR 解释缩短敏感文件暴露时间，并更新文档索引。Addy 并不是唯一能做对的组。

### 未点名时是否会读取 Skill

- 期限变更题：仅安装组两轮均有执行成功的 `cat .agents/skills/documentation-and-adrs/SKILL.md` 日志，说明本环境下两次确实读取了原文。
- 内部重构题：仅安装组没有完整读取原文的记录，其中一轮仅搜索了 Skill 的相关词；两轮都只改代码，没有改文档。
- 显式组四轮均完整读取原文，内部重构时仍判断无需更新文档。

这是可观察的读取行为，不是跨客户端触发率。仅安装组的小改动没有完整读取不应判失败，因为任务没有改变文档表达的事实。

## 对采用决定的意义

Addy 的 ADR 生命周期规则与本轮差异相符，可以继续作为少量补充的候选。当前没有证据表明它提高了文档发现覆盖率：两组基线也主动找齐并更新了当前说明和图，且目录很小、入口明确、关键词直接命中。

因此，**不把本轮结果解释为“安装 Addy 就能防止漏更新”，暂不据此安装整套 Addy 或改变已选 Matt 主流程。** 在核心痛点上，仍需在实际项目中检查文档影响范围是否进入实现收尾和独立审阅。若后续试用 Addy，采用理由应限于文档维护规范，尤其是历史决定保留；它不是同步保障机制。

本次没有新建文档同步 Skill，也没有修改 Matt 或 Addy 原文。两个案例、每组两轮、作者非盲评，无法估计稳定胜率；没有覆盖大仓库、无索引资料、长会话、多人并行变更或其他 agent。也没有证明该 Skill 对 Matt 本身已有 ADR 规则提供额外收益。
