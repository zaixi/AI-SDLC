# 四个写作 Skill：单轮实测

**本轮没有全面胜出者。先前“优先试 i-have-adhd”的建议未获支持：它答案前置做得好，但经常添加步骤、进度、估时和下一步。四份原版都没有稳定消除重复。**

使用 OpenCode 1.14.28 + DeepSeek Flash，3 题 × 4 组，每组合一次，共 12 个独立会话。Grok 4.7 在正式测试前连通失败，所有正式题目统一使用 DeepSeek Flash。请求带 `reasoning_effort=high`，已核实实际请求字段，未核实供应商如何实现它。

## 结论与例证

| Skill | 本轮较好的部分 | 直接使用的主要问题 |
|---|---|---|
| writing-clearly-and-concisely | 决策题回复短；英文改写的最终文件准确、易读 | 概念题有重复清单；改写题先讲修改过程、输出一版，纠正自己的拼写错误后又输出一版 |
| humanizer | 决策题没有创建多余文件，因果清楚；英文终稿紧凑 | 改写题原样执行“草稿＋检查清单＋终稿”，用户仍需读两版；终稿还丢掉“最多两次”的显式限定 |
| asd-ste100 | 决策题聊天正文较完整；英文改写保留条件和不确定性 | 中文题额外解释如何套用英文规则；生成双语重复文件；英文短句化后仍保留重复总结 |
| i-have-adhd | 概念题结论最先出现，有用的竞态示意；调用少、耗时低 | 决策题四组最长，添加无依据估时、状态重述、操作步骤、Next；英文改写提高了效果声明的确定性 |

### C01：向初学者解释重试、幂等与并发漏洞

四组都识别了“先查再插、无唯一约束”的竞态，读者能找回核心答案。但每组都把部分要点放进定义、条件清单、实施步骤、总结等多个位置重复解释。必要的示意与例子有价值，问题在于后续清单重复，而不是回答超过某个字数。

- clear：先列约束条件，再列扩展问题，再列判断清单，最后重复结论；“重试保证至少送达一次”没有交代成立条件。
- humanizer：多次强调请求 ID 要复用，末尾又附同一提醒；还有技能使用说明和网络投递旁支。
- STE：聊天正文较短，但另写 2071 字符说明，包含开头结论、五条条件、检查表、末尾总结。按聊天长度排名会漏掉这部分负担。
- ADHD：示意图与 SQL 帮助理解并发；随后又列五项检查、修复步骤、估时和下一步。“重试负责一定要成功”过强，有限重试不能保证成功。

本题无明确赢家。不能把必要解释删掉后只按短回答评优，也不能因内容完整就忽略重复。

### C02：已有上下文下，判断能否上线

四组都给出正确决定：暂不上线，明确产品要求“同 ID、不同金额必须拒绝”尚未实现。

只看聊天正文，STE 的 273 字符相对完整；但另写 980 字符的中英文同义文件。clear 的 260 字符也短，不过“造成账实不符”把可能影响写成确定后果，且另有重复文档。

综合全部交付，humanizer 的 363 字符较合适：给结论和关键依据，未落多余文件。它仍有可删的解释和“本轮是讨论，没有需要写出的文件产物”一句。

ADHD 共 674 字符，加入状态行、四个行动步骤、30–60 分钟/半天的估时、Next，还把示例 HTTP 409 当成必须如此的要求。用户问的是判断和依据，这些扩展增加了负担。

### E01：为支持工程师改写英文发布说明

最终正文偏好 clear：168 个英文单词，保留版本、超时范围、最多重试次数、同一 ID、400 不重试、启用/回滚方式、已有文件保留及内存效果未知。但用户实际收到的全部文本有 4138 字符，过程说明与两次展示抵消了正文压缩的收益。

humanizer 的终稿结构紧凑，完整回复却包含草稿、剩余模式清单和终稿。原文 `up to two times` 被改成 `twice`，省掉了显式上限含义。不能只看它“去 AI 味”的外观。

STE 的正文保留了主要事实和限定，但仍留下 `The response timeout is now longer`，并在末尾用三句总结再次复述已讲内容。这说明句子变短和段落去重是两件事。

ADHD 保留了大部分细节，却把 `may reduce failures` 改成 `are less likely to fail`，将可能的收益写得更确定；另加启用工作区的 Next，偏离发布说明改写。该题的服务端终稿正常结束，但 CLI 漏记；本报告从原始响应恢复内容，交付异常单独记录。

## 方法与限制

- 每个会话独立 HOME、工作目录和网络空间，只看自己的 skill、原题及该 skill 的参考文件。仓库、其他 skill、历史回答与评审材料不可见。12 组均实际读取了 SKILL.md。
- 显式调用 skill，包括禁止自动触发的 ADHD；没有测试自动触发。原文未删改，参考文件按需读取，未强制所有组只输出终稿。工具环境不提供子代理。
- C02 的历史上下文写入当次题目，不是真实持续会话。因此没有验证 ADHD 的跨轮持续生效。
- 通用 harness 提示“需要文件产物时写入 /work”，且提供写文件工具；没有要求写文件，也没有禁止。额外文件的产生可能与该提示、模型和 skill 共同有关。不能单独归因于 skill。
- 当前助手设计题目并评审。虽然输出做了匿名编号，部分回复自行透露 skill 名称，且检查工具记录时曾看到一份正文，故**不是严格盲评**。未用其他模型独立打分，未做人类读者实验。
- 仅 3 题、每题一次，没有无 skill 基线；只能说明本轮四种条件下的差异，不能证明它们比无 skill 更好或更差，也不能推断稳定排名。
- 11 组有正常 CLI 文本，1 组服务端完成但 CLI 漏记。未重跑失败题，没有用当前助手代写答案替换模型输出。

## 后续判断

本轮不支持直接选一个原版作为全局写作默认，也不支持把四份叠加。若继续验证，最有价值的是加入无 skill 基线，判断这些问题主要来自模型/客户端，还是 skill 引入。若用户只需要现成改写工具，clear 的最终正文值得参考；若关心日常对话，本轮 humanizer 的决策回答较合适，但它的默认长文改写流程明显不符合“只给有用结果”的偏好。

原始文件保存在本机持久目录，未上传公共附件。依赖提交与输出校验值见 protocol.json。无需修改已有 visual-explanation skill。
