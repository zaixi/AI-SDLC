# 写作 Skill：五道扩展题比较

**本轮不支持 clear 明显胜出。humanizer 在进展摘要和非技术解释上更值得参考，clear 与 humanizer 的英文邮件正文都合格。ADHD 的强行动导向继续引入无关步骤、无依据估时，邮件还漏掉了重要限定。**

新增 5 题 × 4 个条件，共 20 个独立会话，全部正常完成，每组合一次，无补跑。模型仍为 deepseek-flash，客户端 OpenCode 1.14.28。本轮不含 asd-ste100，未改动三个 skill，也未测试精简指令。

## 逐题判断

| 案例 | 本轮判断 | 关键证据 |
|---|---|---|
| C03 简单超时问答 | 无合适赢家 | 四组都答对 120 秒为 2 分钟、100 秒未到阈值，但都扩展了不必要内容 |
| C04 项目进展更新 | humanizer 正文较好 | 保留完成项、阻塞、未承诺时间及上线条件；其他组有过强推断或虚构估时 |
| C05 可执行排查方案 | 无明确赢家 | 都有可用的取证步骤，但不同程度膨胀或把实验线索写成确定归因 |
| C06 书店因果解释 | 倾向 humanizer | 连贯解释替代原因，说明前后比较和剂量关系的局限；仍有重叠解释与长段落 |
| E02 客户邮件改写 | clear 与 humanizer 正文均合格；整体更倾向 humanizer | 均保留承诺和不确定性，humanizer 完整回复更短；ADHD 删除了确认时间的预期 |

### C03：回答结束后能否停下来

题目只需回答两个事实。无 skill 用 292 字符，复述默认值和无限制设置，并说明没有文件。clear 用 257 字符，添加取消超时建议、假设文档可能使用其他单位及没有文件的声明。humanizer 用 512 字符，先解释技能不适用，再补充默认值与多个秒数例子。

ADHD 最短（226 字符），但把换算和阈值重复三次，末尾要求改配置并重启。题目没有要求调整配置，也没有提供必须重启的信息。不能把它当作“最短所以最好”。

这题暴露的不是语句润色能力，而是是否知道何时停止。三个现成 skill 都没有解决它。

### C04：信息完整与不确定性

humanizer 的最终正文 214 字符，事实基本齐全：开发和 CSV 已验证，XLSX 待权限，周五取决于验证结果，公告未发。它没有把未测说成已可用。不过完整回复 418 字符，又讲了一遍写法和负责人关心的三件事；正文也分成多段，没有严格按“一段”交付。

clear 正文 260 字符，却用了 811 字符完整回复讲如何遵守写作规则。正文称权限时间“将直接决定能否按期上线”，弱化了获得权限后测试仍可能不通过的条件；“唯一的卡点”也超出明确已知范围。

无 skill 同样声称“除权限外没有其他阻塞”，并附推动权限的建议、三步行动及一句话总结。ADHD 写出“验证约 30 分钟”“公告约 5 分钟”，原题没有这些依据。

本题倾向 humanizer，但仍需删去正文外的解释，才能直接交付。

### C05：需要细节时是否有效展开

四组都能提出复现基线、分段计时、采样和按结果选择路径，未简单断言根因就是索引。长回答在这题有理由，不能按字数机械惩罚。

无 skill 的附带方案达 6739 字符，列出大量实验、证据清单、陷阱与决策树，若干内容反复出现。它先把原因称为“互斥”，后面又承认可能存在叠加开销；还写“避免同时跑 profiler 与被测应用”，与方案中的采样动作矛盾。

humanizer 的 4345 字符方案有明确证据和分支，但扩展到七类平台工具、九个步骤和末尾归因汇总。部分推断仍过强，比如把程序化首次查询触发卡顿直接解释为懒初始化，缺少排除该路径首次读取或计算的条件。

clear 的 2711 字符方案相对收敛，读者能跟着取证。但“再次启动仍卡”就“排除 OS 文件缓存冷读”、“预热后不降”就排除索引，都是证据不足的排除。前文说开发者工具不能用于下结论，后文又用它采样，未清楚区分采样定位与无采样基准。

ADHD 的方案 2244 字符，第一步清楚、分支好找；但四个时间戳只能得到三个相邻区间，却要求填 init/load/filter/render 四段数字。它还把“预热后仍卡”直接写成“不是初始化”，并多次给出没有任务依据的耗时估算。

这些问题显示写作 skill 不能替代领域推理，也不能靠减少字数自动解决。该题没有明显胜出者；ADHD 的行动组织方式可以参考，不能照收整个方案。

### C06：解释需要帮助理解，而非只堆术语

humanizer 用连续段落讲清观察与推断的区别、替代解释、前后比较的不足、抽签候补对照和匹配比较，并明确读书会仍可能有效；还说明剂量关系可能来自原有兴趣。相比其余组，解释的连接较自然。但反向因果与自选偏差仍重叠，长段落不易扫读；随机邀请与随机获得名额的区别也没有展开。

clear 较短，但先列替代解释，再列四问，末尾再次总结。还将“共同原因可能解释相关”写成“彼此没有因果关系”，表达过强。随机邀请与实际参加的效果未作区分。

ADHD 给了三问、四条线索、五种验证方式、记忆锚和下一步，结构多于必要，且称随机化“自动平衡掉”干扰、估计小书店 4–8 周能看出趋势，缺少条件。无 skill 则展开到 2485 字符，并重复流程、口诀和最终结论，还把剂量反应讲得过于必要。

这题倾向 humanizer，依据是解释质量和限定，而非字数最少。

### E02：保留承诺的自然邮件

clear 与 humanizer 的正文都保留了：原定周二、分析已完成、三月数据待确认、今天不能发终稿、今天可按需发未验证草稿、预计周四确认但不保证，以及无论是否确认都会在周四 3 p.m. 前更新。

humanizer 文件 705 字符，语气自然、适当道歉；clear 文件 745 字符，也可直接使用。但前者整次回复 1702 字符、后者 2615 字符，都加入过程与改动说明。clear 还有多条英文进度前言。humanizer 的修改说明声称删掉了 `even if we are still waiting`，正文却保留了这一关键条件，说明额外说明本身也可能不准确。

无 skill 保留事实，却仍用较多客套话，文件 943 字符。ADHD 文件最短（639 字符），但漏掉“预计周四得到确认、时间不保证”，把邮件改成 Next step 和 Status，并两次要求回复 yes。这不是等价压缩。

## 对框架选择的影响

上一轮推荐 clear，是因为它的目标与清晰简洁相符，且英文发布说明终稿好。本轮需要降低这项推荐的确定性：**clear 仍可作为改造起点，但数据不支持它是明显优于 humanizer 的现成框架。** humanizer 应继续保留为主要候选，尤其值得参考它的摘要和自然解释；ADHD 更适合有明确行动需求时借鉴，而非通用默认。

两轮共覆盖八题，仍没有哪个原版可以直接作为“去废话”的完整答案。共同需要解决的是：控制当前回答范围、避免重复、直接交付成品，并保留条件和不确定性。没有证据支持继续叠加更多风格规则。下一轮若改造，应比较明确的精简版本与原版、无 skill，而不是继续堆原版技能。

本轮未创建、安装或修改写作 skill；未改变全局指令。

## 方法与验证

- 案例与核对项在运行前写入并哈希固定；当前助手设计并评审，属于非盲定性评审，没有独立评审模型或人类读者实验。
- 每组合独立 HOME、工作目录及网络空间。五个无 skill 会话输入目录为空，十五个 skill 会话均实际成功读取各自 SKILL.md，所见文件与固定快照逐字节一致。
- 正式请求均核实 deepseek-flash、reasoning_effort=high、max_tokens=16384，未发送 temperature。接受字段不证明供应商内部实现。
- 不测试 skill 自动触发或跨轮持续效果；harness 不提供子代理。保留通用文件交付提示及工具权限，额外文件和过程说明可能由模型、skill 与 harness 共同产生，不能全部归因于 skill 原文要求。
- 20/20 正常结束，未达预算上限，没有重跑、替换模型或恢复服务端漏记文本。旧结果保持原样，不混作本轮重复样本。
- 每题一次，不能给稳定排名或胜率。原始输出、请求及 gallery 留在协议记录的本机持久目录，未上传公共附件。
