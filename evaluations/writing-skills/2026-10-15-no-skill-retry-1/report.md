# 无 skill 基线重试：五组比较

三题均成功，补齐后不能得出“无 skill 更强”。四个 skill 在判断题中都让聊天回答更短，但没有一个同时解决重复、交付负担和语义准确性。

本轮仅跑无 skill，OpenCode 1.14.28 + deepseek-flash，原题、参数和工具权限沿用上轮，每题一次。四个 skill 使用已有的十二份输出，没有重跑。之前 C01/C02 的 HTTP 429 记录原样保留，不计入质量评价；E01 本轮首次执行。

### C01：解释概念

无 skill 能解释先查再插的竞态，并指出需要数据库唯一约束和原子写入；并发过程的例子有用。但它随后扩展七项注意事项，包括过期窗口、退避和多实例部署，再用四条结论复述，开头和结尾还分别声明无需文件。重试提供“至少执行一次”的说法也缺少成立条件。

四个 skill 的聊天文本都短于基线，但三个另有文档，且各组仍重复清单或总结。这里可以看到部分压缩收益，不能认定已有某个 skill 彻底解决了问题。

### C02：判断能否上线

五组结论均正确：同 ID、不同金额必须拒绝的要求未满足，不能上线。

基线用 1203 字符回答，把同一理由放进结论、四条解释、对已通过测试的说明和末尾总结，还扩展指纹计算、参数规范化和测试步骤。四个 skill 都缩短了聊天回复。综合交付，humanizer 的 363 字符且无额外文件较合适；clear 和 STE 虽聊天更短，却另附重复文档。ADHD 仍加入估时和下一步。

这是本轮最明确的 skill 收益：已有上下文下，回答能更集中。不过各组仍有措辞过强、额外流程或无关收尾，不能据此将整份原版设为全局默认。

### E01：英文改写

基线保留了大部分事实，但在 Summary 和 Expected impact 重复收益与限制，在 Support notes 再讲重试规则；还附修改说明。它把仅针对 HTTP 400 的规则扩展成“Client errors such as HTTP 400 are not retried”，并将不得宣称内存改善扩展为不得宣称性能或内存改善，超出原文。

clear 的最终文件更紧凑，且保留主要限定；但完整聊天达 4138 字符，草稿、修改过程和重复展示抵消了优势。STE 相对克制，却仍有重复总结。humanizer 的草稿加终稿流程和 ADHD 的效果措辞变化也仍存在。

因此需分别判断“最终正文是否好”和“用户是否容易拿到它”。无 skill 不是更好的默认改写方案，原版 skill 的完整流程也未必符合只要成品的要求。

## 下一步建议

先尝试一条短的通用写作指令，针对回答范围、观点去重、保留限定和直接交付；暂不叠加四份 skill，也不新建复杂规则体系。长回答仍可用于需要充分解释的题目。

候选指令（尚未测试）：

> 先回答当前问题，再给理解或决策所需的依据。根据已有上下文省去读者已知的背景；同一观点通常解释一次，例子应增加理解。保留关键条件、例外和不确定性。除非用户要求，只交付最终内容，不附草稿、修改过程、重复总结或无关的下一步。需要充分解释时可以写长。

本轮只完成授权的基线重试，没有将候选指令安装为全局偏好，也没有测试新条件。现有数据支持试这条路线，不证明它一定优于原版 skill。

## 验证与限制

- 三题均有正常 CLI 正文，共 6 次模型请求；任务耗时之和 53.07 秒，输入 token 30795、输出 token 9235。usage 包含重复上下文及推理，不是净正文或账单；不同批次延迟不可直接归因于 skill。
- 输入文件哈希与上一轮相同。隔离审计确认没有 skill、仓库、全局配置或评审材料；正式请求参数为 deepseek-flash、reasoning_effort=high、max_tokens=16384，未发送 temperature。供应商接受参数不证明其内部实现。
- 保留通用“需要文件产物时写入 /work”和写文件工具。基线也主动生成了文件，说明不能把额外交付全部归因于 skill。
- 仅三题、每题一次，当前助手做非盲定性评审；没有独立读者实验，不能推断稳定排名。四个 skill 的结果来自前一批次，服务状态可能不同。
- 原始输出、请求、隔离日志和交互对照页留在本机持久目录，未上传公共附件。仓库仅保存报告、协议、原题和方法。
